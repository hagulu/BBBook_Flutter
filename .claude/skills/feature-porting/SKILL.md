# 기능 이관

## 규칙

- 기능 분석 문서를 먼저 확인한다.
- 분석 문서는 docs/porting-reference 경로 하위에서 확인한다.
- 전달받은 기능만 구현한다.
- 문서에 없는 기능이나 동작은 추가하지 않는다.
- Flutter 프로젝트 구조와 아키텍처에 맞게 구현한다.
- 구현 방식은 Flutter에 맞게 변경하되 기능과 UX는 최대한 동일하게 유지한다.
- 기존 공통 위젯, 상태관리, 유틸을 우선 재사용한다.
- 변경 범위는 필요한 파일만 수정한다.

## 원본 프로젝트

- 원본은 Next.js 프로젝트이다.
- 필요한 경우에만 `../../front/bbbook/` 내부를 참고한다.
- 실제 파일 확인이 필요하면 먼저 이유를 설명하고 사용자에게 확인받은 후 진행한다.

## 모호한 사항

- 요구사항이 모호하면 추측하지 않는다.
- 다른 기능과 연계 구현이 필요하다고 판단되면 임의로 구현하지 말고 먼저 질문한다.
