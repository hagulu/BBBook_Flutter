# 내 기록 내보내기·가져오기

설정의 두 메뉴는 로컬 DB를 기준으로 동작한다. 별도의 서버 조회/저장 API는 호출하지 않는다. 원격 이미지의 실제 파일을 확보할 때만 기존 이미지 저장소의 다운로드를 사용한다.

## ZIP 형식 (version 1)

- `books.csv`: UTF-8 BOM, CRLF 행 구분, 모든 셀에 CSV 따옴표 escaping. `statsTotalPages`는 종이책 기준 쪽수, `displayTotalPages`는 판본 쪽수이며 후자가 없으면 전자를 사용한다. `tags`는 태그 이름을 `|`로 결합한다.
- `notes/{책 제목}/{노트 제목}.html`: 노트별 한 파일. 메모 조각은 `sortOrder` 순이며 타입·페이지·강조·사진을 표시한다.
- `reflections/{책 제목} - {독후감 제목}.html`: 기존 Quill/Tiptap 어댑터를 사용해 문단·제목·목록·인용·인라인 서식·이미지를 표시한다. 외부 스크립트나 스타일 리소스를 사용하지 않는다.
- `images/`: 책 표지·메모 사진·독후감 이미지. 기능별 동일 이미지 출처는 한 파일로 합치며 HTML과 JSON이 공동 참조한다. 로컬 사본 → 기존 이미지 캐시 → 다운로드 순으로 확보한다. 확보 실패 이미지는 참조와 함께 제외하고 완료 메시지에 개수를 표시한다.
- `bookkureomi.json`: `backupVersion: 1`, `exportedAt`(UTC), `books`, `notes`, `memos`, `reflections`, `tags`. 가져오기는 이 파일과 연결된 이미지만 읽는다.

포맷의 필드 규격은 `models/record_archive.dart`의 버전 1 스키마에 고정한다. DB 컬럼 대응은 `RecordArchiveDao`에서만 처리한다. 로컬/서버 PK, 소유자 ID, dirty 상태, 실제 기기 경로는 JSON에 넣지 않는다. 카테고리는 이름과 마스터 code를 저장하고 가져올 기기의 카테고리 캐시에서 ID를 찾는다. 서버의 도서관 PK처럼 로컬에 논리적 대응 정보가 없는 외부 참조 ID는 옮기지 않는다.

책·메모·독후감의 export ID는 기존 `clientRequestId` UUID를 이용한다. 없는 기존 행은 내보내기 스냅샷 트랜잭션에서 UUID를 백필하되 dirty 상태는 바꾸지 않는다. 노트는 export UUID와 하위 메모 관계로 표현한다. 태그는 이름 자체로 식별한다. DB 구조가 바뀌면 DTO와 DAO의 대응만 조정하며, 포맷 변경은 새 버전 파서를 추가한다.

## 가져오기 정책

기존 Import 문서의 ISBN·clientRequestId·태그명 대응 기준을 따른다.

- 새 항목은 음수 로컬 ID를 새로 발급하고 서버 ID를 비운다. 신규 책·메모·독후감에는 export UUID를 clientRequestId로 저장한다.
- 같은 UUID의 활성 책은 보존한다. 같은 ISBN으로만 대응된 책은 기존 로컬 ID와 표지를 보존하고 가져온 책 정보·독서 정보를 적용한다.
- 노트는 하위 메모 UUID로 대응한다. 메모 없는 노트는 같은 책의 동일 제목인 빈 노트와 대응한다. 한 가져오기 안에서 이미 연결한 빈 노트를 다른 노트에 중복 할당하지 않는다.
- 같은 UUID의 활성 메모·독후감은 기존 내용을 보존한다. 부모 관계가 다르면 전체 가져오기를 중단한다.
- 태그와 연결은 기존 TagDao의 이름별 재사용·삭제 태그 재활성화·중복 연결 방지·책당 최대 10개 정책을 사용한다.
- 이미지 존재·포맷·CRC, JSON 필드·버전·관계를 먼저 검증한다. 이미지를 UUID 파일명으로 현재 앱 지원 디렉터리에 복사한 뒤 한 DB 트랜잭션으로 반영한다. 실패 시 복사 파일을 정리하고, 성공 시에도 기존 기록 재사용으로 불필요해진 사본은 정리한다.
- 현재 계정이 바뀌면 작업을 중단한다. 가져온 데이터는 dirty로 남으며 서버 모드는 기존 백그라운드 동기화가 전송하고 로컬 모드는 그대로 보관한다. CREATE 뒤에도 전체 기록/책 정보 dirty 필드를 남겨 기존 후속 PATCH가 실행되게 한다.

내보내기/가져오기 및 저장 모드 전환은 동시에 실행하지 않는다. 공통 AppLoading과 PopScope로 중복 조작·뒤로 가기를 막으며, ZIP 압축 작업은 일회성 isolate에서 처리한다.

## 파일 취급

파일명은 금지 문자·예약어·앞뒤 공백·끝 점을 정리하고 최대 60 Unicode 문자로 제한한다. 대소문자를 무시한 충돌에는 `(2)`부터 suffix를 붙인다. JSON과 HTML 본문의 실제 제목은 유지한다.

ZIP은 디스크에 전체 압축 해제하지 않는다. 절대 경로·상위 경로·심볼릭 링크·중복 ZIP 엔트리를 거부한다. 지원 한도는 ZIP 512MB, 압축 해제 합계 1GB, 엔트리 50,000개, JSON 및 이미지 한 파일 32MB다. 내보내기도 같은 범위로 제한하며 범위를 넘는 이미지는 누락 안내 대상이다.

내보내기는 OS 파일 저장 창을 열어 사용자가 폴더와 파일명을 선택하게 한다. ZIP은 먼저 앱 임시 디렉터리에서 만든 뒤 선택한 위치에 저장한다. 실제 저장/파일 선택 UI는 iOS·Android 기기에서 별도 확인해야 한다(작업 규칙상 앱 실행은 하지 않음).
