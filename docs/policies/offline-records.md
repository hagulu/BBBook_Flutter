# 오프라인 기록 사용 정책

## 앱 진입과 로컬 사용

- 기록 DB에 보관한 계정 소유자로 먼저 화면에 진입한다. 토큰 갱신과 사용자 조회는 화면을 막지 않는다.
- 시작 시 인증 확인 중이거나 인증 상태 변경 후 라우터 전환을 기다리는 프레임에는 배경만 표시한다. 로그인 상태에서 온보딩이 잠깐 노출되지 않게 한다.
- 기존 설치는 최초 동기화 완료 메타데이터, 저장 모드 소유자, 노트·독후감 소유자가 한 계정으로 일치할 때 복원한다. 소유자를 확인할 수 없는 데이터는 임의의 계정에 연결하지 않는다.
- 완료 이력이 있는 빈 책장도 사용 가능한 로컬 데이터로 취급한다. 실제 기록이 있으면 최초 동기화 메타 형식이 달라져도 초기 다운로드 화면으로 되돌리지 않는다.
- 아직 아무 기록도 내려받지 못한 신규 계정은 기존 최초 다운로드 화면과 재시도를 유지한다.
- 책장 목록, 기록 필드, 노트·메모, 독후감은 로컬 조회·편집 경로를 사용한다. 책 추가·정보(제목/저자/출판사/카테고리/쪽수)·표지·출처 수정과 삭제도 로컬 저장 직후 완료하고 서버 전송은 뒤에서 진행한다.
- 프로필 요청이 실패하거나 지연돼도 저장한 사용자 정보로 마이 화면과 로컬 독서 리포트를 사용할 수 있다. 통계의 카테고리 보조 정보도 네트워크를 기다리지 않는다.

## 인증과 네트워크 복구

- 인증이 필요한 요청은 세션 준비를 기다린다. 앱 재실행 후에는 refresh와 사용자 소유자 확인을 마친 뒤 요청한다. 유효 시간이 끝나기 전 토큰을 갱신한다.
- 동시 요청은 하나의 갱신 작업을 공유한다. 늦게 도착한 이전 토큰의 401은 이미 갱신된 토큰으로 한 번 재시도한다. multipart 재시도는 새 FormData를 사용한다.
- 연결 실패·타임아웃·서버 오류로 로컬 기록이나 refresh token을 삭제하지 않는다. 일시적인 refresh 실패를 원래 요청의 401로 바꿔 전달하지 않는다.
- 네트워크와 갱신 실패 후 15초 동안 자동 반복 요청을 제한한다. 최초 다운로드·프로필의 재시도 버튼과 책장·노트·독후감의 수동 새로고침은 이 대기를 해제한다. 인증 무효 상태는 해제하지 않는다. 요청에는 연결·송신·수신 타임아웃이 있다.
- refresh 거부 또는 갱신 후 재시도까지 401이면 서버 인증을 해제한다. 저장 모드와 관계없이 로컬 기록·이미지·미전송 변경은 보존한다. 마이 화면의 재로그인 버튼으로 서버 연결을 복구한다.
- 계정 변경·로그아웃 전에 시작된 요청을 새 토큰으로 전송하거나, 늦은 응답을 새 계정에 적용하지 않는다. 대기 중인 기록 push도 시작 당시 세션을 검사한다.

## 동기화

- 로컬 화면 진입 후 인증 → 책 → 노트 → 독후감 → 태그 순서로 동기화한다. 각 기능의 기존 dirty push → pull 정책을 재사용한다.
- ISBN 연결·서재 포함 여부·기록 공개 설정처럼 로컬 기록에 의존하는 통신은 먼저 공통 동기화에 합류한다. API 클라이언트의 준비 함수/옵션만 사용하고 타이밍·중복·재시도 정책은 BackgroundRecordSync 한 곳에서 관리한다. 일반 검색 등 모든 요청을 막지는 않으며, 동기화 자체 요청에는 선행 동기화를 적용하지 않아 순환 대기를 막는다.
- 선행 동기화를 새로 시작한 요청은 최대 3초만 기다린다. 이미 동기화가 실행 중이면 별도로 기다리지 않으며, 시간 초과는 동기화 취소를 뜻하지 않는다. ISBN 연결에 필요한 해당 책의 미전송 편집 확인은 유지한다.
- 앱 복귀와 API 통신 성공 시 복구를 확인한다. 앱이 활성화된 동안 30초마다 확인하며 중복 시도는 최소 15초 간격으로 제한한다.
- 미전송 변경이 없고 최근 전체 순서가 성공했으면 10분간 동기화를 생략한다. dirty가 남으면 최근 성공 시각과 관계없이 다음 확인 때 재전송한다.
- 같은 기능의 자동 동기화·화면 새로고침·저장 방식 이전은 Repository의 진행 중인 동기화를 공유한다.
- 저장 방식 이전 중에는 자동 동기화의 다음 단계를 진행하지 않는다. 로컬 저장 모드에서는 기록을 서버와 동기화하지 않는다.
- 기존 로컬 데이터로 진입한 후에는 초기 적재의 삭제·재삽입 경로를 사용하지 않고 각 기능의 dirty 보호 동기화를 사용한다.
- 백그라운드 책 생성이 서버에서 거부돼도 이미 사용자에게 저장 완료한 로컬 기록을 자동 삭제하지 않는다. dirty 상태로 보존한다.
- 책 CREATE/수정/삭제의 영구 오류는 행별 실패 사유·횟수·다음 시각을 저장해 10분부터 최대 6시간까지 재시도 간격을 늘린다. 보류된 책과 그 하위 기록만 남았을 때는 30초 주기 전체 동기화를 촉발하지 않는다. 새 로컬 편집·삭제 또는 수동 책장 새로고침으로 재시도를 앞당긴다. 수동 새로고침 후에도 거부된 기록이 남으면 기존 스낵바로 안내한다.
- 표지 사본이 유실됐으면 서버 표지는 유지하고 나머지 책 정보·기록부터 전송한다. 표지 교체 의도만 미전송으로 보존하며 `local_cover_missing` 사유로 재시도를 늦춘다. 표지를 다시 선택하면 전송을 재개한다.
- 삭제한 책은 목록·통계에서 즉시 제외하고 하위 기록을 정리한다. 서버 DELETE는 재시도하며 404는 삭제 완료로 취급한다. 삭제 표식을 남겨 늦은 PATCH·pull 응답이 책을 복원하지 못하게 한다.
- 응답을 잃은 CREATE는 같은 clientRequestId로 복구한 뒤 삭제한다. 같은 ISBN 재등록은 이전 삭제의 서버 반영 뒤에 전송한다.
- 책 정보·출처·기록 필드가 함께 바뀌면 책별 큐에서 순서대로 전송한다. 일부 요청만 성공해도 로컬 입력값은 유지하고, 다음 요청의 서버 updatedAt 기준값만 갱신한다. 늦은 응답이 최신 편집을 덮어쓰지 않는다.
- 사용자가 고른 표지는 업로드 후에도 기기 사본을 유지한다. ISBN 연결은 미전송 편집을 먼저 동기화한 뒤 같은 책별 큐에서 수행한다.

## 다른 계정과 로그아웃

- 같은 계정 재로그인은 기록과 동기화 대기 내용을 유지한다.
- 다른 계정 로그인은 공통 확인창으로 기존 기기 기록 전체 삭제 및 미전송 기록 복구 불가를 알린다.
- 취소하면 새 계정 토큰을 저장하지 않고 기존 기기 기록을 유지한다.
- 확인하면 기존 책·노트·메모·독후감·태그·이미지·동기화 메타데이터와 저장 모드를 정리한 뒤 새 계정 세션을 저장한다. 로컬 정리에 실패하면 새 계정으로 전환하지 않는다.
- 사용자가 직접 선택한 로그아웃은 기존 전체 로컬 정리 동작을 유지한다. 자동 인증 해제와 구분한다.

## 기존 제한

- 서버 저장 모드의 ISBN 연결, 검색·커뮤니티·프로필 수정은 온라인 기능을 유지한다.
- 이미지 오프라인 표시는 기기에 이미 확보한 사본에 한정된다. 서버에만 있는 이미지를 인터넷 없이 새로 가져올 수는 없다.
- 기록 필드만 바뀐 경우 기존 409 정책을 유지한다. 책 정보 조합 저장 중 409는 부분 성공으로 인한 값 유실을 피하도록 최신 로컬 편집을 보존하고 다음 시도에서 재전송한다.
- 중복 ISBN CREATE의 자동 병합은 하지 않는다. 양쪽의 노트·독후감·진행 상태를 합치는 정책이 정해지기 전에는 서버 사본과 미전송 로컬 사본을 모두 보존한다.

## 검증 항목

정적 분석 외 아래 시나리오는 실제 앱/테스트 실행이 허용될 때 확인한다.

- 기존 서버/로컬 저장 모드 각각에서 오프라인 재실행, 빈 책장, 구형 동기화 메타데이터 복원.
- refresh 및 사용자 조회의 타임아웃·5xx 중 로컬 진입, 이후 앱 복귀/통신 재개 시 동기화.
- 여러 API의 동시 401, 늦은 401, refresh 일시 실패, refresh 401/403, multipart 재시도.
- 오프라인 책 추가·기록/노트/독후감 수정 후 재실행 및 연결 복구.
- 책 정보·표지·출처·쪽수 연속 수정 중 지연 응답, 부분 요청 실패, 삭제와 CREATE의 경합, 삭제 후 같은 ISBN 재등록.
- 인증 무효 후 로컬 편집, 같은 계정 재로그인, 다른 계정 경고 취소/확인.
- 새 계정 로그인과 이전 세션의 느린 응답/대기 push가 겹쳐도 기록이 섞이지 않는지 확인.
- 저장 방식 이전과 자동 동기화가 겹친 경우, 최초 다운로드 실패 후 재시도.
