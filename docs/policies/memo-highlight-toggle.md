# 메모 조각 강조(하이라이트) 토글 정책

텍스트 메모 조각 본문 편집기에서 강조 버튼이 어떻게 동작해야 하는지에 대한
정책 문서. 모바일 `MemoHighlightController`
(`lib/features/book_memo/screens/widgets/highlight_text_field.dart`)의 구현
기준이며, 다른 화면/플랫폼에 같은 편집기를 다시 구현할 때 참고한다.

## 저장 형식

- 강조 위치는 본문 `content` 문자열 안에 `::hl[[강조할 내용]]` 마크업으로만
  저장한다(웹과 동일 규칙). 별도 컬럼/좌표 테이블 없음.
- `isImportant`는 `content`에 `::hl[[]]`가 하나라도 있으면 `true`, 하나도
  없으면 `false`인 파생값이다. 사용자가 직접 켜고 끄는 값이 아니다.
- 사용자에게는 마크업 없는 평문만 보인다. 강조 영역은 노란 형광펜 배경으로만
  표시한다.

## 강조 상태 판단(커서 위치 → 활성 여부)

- **커서 앞 글자 기준**으로 판단한다. 커서가 강조된 글자 바로 뒤에 있으면
  "이 위치는 강조 상태"로 본다(오프셋 0이면 예외적으로 뒤 글자를 본다).
- 선택 영역이 있으면 "선택 전체가 강조돼 있는가"로 판단한다.
- 사용자가 명시적으로 켜거나(다음 입력을 강조) 끈(다음 입력을 강조 안 함)
  세션 오버라이드가 있으면 그 값이 이 상속 판단보다 우선한다.
- 이 오버라이드는 **커서가 실제로 이동할 때만** 초기화된다. 텍스트는 그대로인
  채 커서 방향성(affinity) 같은 부가 정보만 바뀌는 이벤트로는 초기화되지
  않는다(IME 조합 중 이런 이벤트가 실제로 발생하며, 여기서 초기화되면 방금
  입력한 글자가 강조를 놓친다).

## 토글 버튼

선택 영역이 있으면 그 영역을 그대로 강조/해제한다. 이하는 **커서만 있을 때**
(선택 영역 없음) 규칙이다.

1. **커서가 강조 덩어리의 맨 뒤 경계가 아닌 그 앞쪽(시작 지점 포함)이나
   안쪽이면 버튼은 아무 일도 하지 않는다.** 커서 위치를 근거로 기존 강조를
   지우거나 둘로 나누는 기능은 없다. 버튼은 비활성(흐리게) 표시하고 탭을
   막는다.
2. 그 외(강조와 무관한 일반 위치, 또는 강조 덩어리의 맨 뒤)에서는 **기존
   강조 데이터를 전혀 건드리지 않고** "다음 입력을 강조할지" 세션 플래그만
   뒤집는다.
3. 뒤집은 결과가 "끄기"이고, **그 지점 바로 앞에 실제로 강조된 글자가
   있었다면**(방금 강조하며 입력했든, 예전에 저장된 강조든) 공백 문자를 하나
   실제로 삽입해 경계를 확정한다. 아직 아무것도 안 쓴 채 켰다가 바로 끄는
   경우는 삽입하지 않는다(빈 세션이라 확정할 경계가 없음).
   - 이 공백 삽입은 실제 텍스트 변경이므로, 마침 IME가 한글을 조합하던
     중이었어도 조합 대상이 우리 편집으로 어긋나며 자연스럽게 끊긴다. IME
     `composing` 상태를 직접 조작해 강제로 끝내려는 시도는 하지 않는다 —
     플랫폼 IME 내부 상태와 어긋나 한글 입력 자체가 깨질 위험이 있다.

## 계속 타이핑(버튼을 안 눌러도 상속)

- 강조된 글자 바로 뒤에서 커서가 시작하면, 버튼을 누르지 않아도 이어서 입력한
  글자는 자동으로 강조를 잇는다(위 "상태 판단" 규칙의 상속).
- 강조 영역 **안쪽**(양옆에 강조 글자가 있는 위치)에 삽입하면 항상 강조가
  늘어난다. 이건 세션 플래그와 무관하게, 삽입 위치를 감싸는 기존 강조 range를
  단순히 늘리는 것으로 처리한다.

## 선택 영역을 교체하는 입력(select-and-type)

- 강조된 텍스트를 드래그로 선택한 뒤(토글 버튼을 거치지 않고) 바로 타이핑해
  덮어쓰는 경우, "커서 삽입 시 앞 글자 상속" 규칙을 그대로 쓰면 안 된다 —
  삽입 위치 바로 앞 글자가 선택 시작 지점보다 앞쪽의, 강조와 무관한 글자일 수
  있기 때문이다.
- 대신 **삭제되는 범위(교체 대상) 전체가 강조돼 있었는가**를 본다. 강조
  버튼의 활성 표시(선택 전체가 강조돼야 활성)와 같은 기준이라, "버튼이
  활성으로 보이던 선택을 타이핑으로 교체하면 새 텍스트도 강조가 유지된다"가
  일관되게 성립한다. 선택이 일부만 강조돼 있었다면(전체 커버리지 아님)
  교체된 새 텍스트는 강조되지 않는다.
- 세션 오버라이드(명시적으로 켜거나 끈 상태)가 있으면 이 판단보다 항상
  우선한다.

## 한글 IME 조합

- 재음절화(받침이 다음 음절 초성으로 넘어가며 글자 수가 줄어드는 경우 등)나
  조합 중 백스페이스는 "한 글자를 다른 한 글자로 교체"가 아니라 임의의
  삭제+삽입 조합으로 들어올 수 있다. 이걸 keystroke마다 새로 판단하면 조합
  도중 강조가 조용히 빠질 수 있다.
- 그래서 **조합 세션 하나에서 쓸 강조 여부는 세션이 시작될 때 한 번만
  정하고, 세션이 끝날 때까지 그대로 고정**한다. 세션 도중 몇 번을 삭제·삽입해도
  같은 값을 쓴다.
- 조합 도중에 토글 버튼을 누르면, 다음 keystroke부터는(같은 세션이 이어지고
  있더라도) 방금 누른 값을 바로 반영한다 — 세션 시작 때 고정한 값을 계속
  우선하지 않는다.
- 렌더링에서는 강조가 있어도 조합 중 밑줄 표시가 사라지면 안 된다. 강조
  구간과 조합 구간이 겹칠 수 있으므로, 둘의 경계를 모두 반영해 구간을 나눈
  뒤 배경색(강조)과 밑줄(조합)을 독립적으로 합성한다.

## 명시적으로 지원하지 않는 것

- 커서 위치만으로 기존 강조 덩어리를 지우거나 둘로 나누는 기능.
- 강조 시작 지점(맨 앞)에서 토글을 여는 기능 — 불필요한 특수 케이스로 판단해
  제외했다.
- IME `composing` 상태를 프로그램적으로 강제 종료하는 처리 — 위험 대비 이득이
  적어 시도하지 않았다.
