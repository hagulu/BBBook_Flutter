# 리뷰 결과

## 요약
- ISBN API 규격과 이전의 표지·필터 수정은 적절하지만, 책 정보의 부분 저장과 오버레이 스낵바의 교체 경쟁·접근성, 일괄 연결 컨트롤의 반응형 문제를 보완해야 한다.

## 문제점
- [상태 정합성][높음] `lib/features/book_record/screens/widgets/book_info_edit_dialog.dart:173`~`:201`은 여전히 한 번의 "저장"을 ISBN 연결 PATCH와 책 정보 PATCH 두 번으로 처리한다. 같은 ISBN 재연결이 허용돼 재시도 자체는 가능하지만, 첫 요청 성공 후 두 번째 요청이 실패한 시점에는 연결과 공용 책 표시 정보가 이미 서버에 반영돼 있다. 사용자가 오류를 본 뒤 팝업을 닫으면 저장 전체가 실패했다고 인식한 상태에서 ISBN 연결만 남는 부분 성공 문제는 해결되지 않는다.
- [생명주기][높음] `lib/shared/widgets/app_snackbar.dart:158`~`:161`은 퇴장 애니메이션용 200ms `Timer`를 지역 변수로 생성해 `dispose()`에서 취소하지 않는다. 이 200ms 안에 바코드 연속 스캔처럼 `replaceCurrent: true`가 호출되면 `:39`에서 기존 `OverlayEntry`를 먼저 제거한 뒤, 남아 있던 타이머가 `:60`의 콜백을 실행해 같은 entry를 다시 `remove()`한다. `OverlayEntry.remove()`는 한 번만 호출할 수 있어 런타임 오류가 발생하고, 오래된 콜백이 새 메시지의 전역 `_entry`/큐 진행을 방해할 수도 있다.
- [접근성][중간] 기존 Material `SnackBar`를 루트 `OverlayEntry`로 교체하면서 `lib/shared/widgets/app_snackbar.dart:172`~`:193`에는 상태 메시지를 자동 안내하는 `Semantics(liveRegion: true)`가 없다. 화면에 새 텍스트가 삽입돼도 스크린 리더 사용자는 성공·오류 메시지를 자동으로 전달받지 못하며, 전체가 `IgnorePointer`라 직접 포커스하거나 닫는 방법도 없다.
- [반응형][중간] `lib/features/book_record/screens/widgets/bulk_link_progress_bar.dart:26`~`:43`은 "즉시 저장", "건너뛰기", "중단" 세 pill을 하나의 `Row`에 고정 폭으로 배치한다. 검색 시트의 가로 패딩을 제외한 폭이 좁은 기기에서는 기본 글자 배율에서도 경계에 가깝고, 시스템 글자 크기를 키우면 줄바꿈이나 축소가 없어 `RenderFlex` 오버플로가 발생한다.

## 개선 제안
- ISBN 연결과 책 정보 수정 사이의 부분 성공 → 연결을 별도의 즉시 반영 액션으로 명확히 분리하고 성공 후 기준 상태를 갱신하거나, 두 변경을 원자적으로 처리하는 서버 API를 사용한다. 두 요청을 유지한다면 두 번째 실패 시 부분 반영 사실과 안전한 재시도·복구 방법을 사용자에게 명확히 안내한다.
- 제거된 스낵바의 퇴장 타이머가 계속 실행됨 → 퇴장 타이머도 필드로 보관해 `dispose()`에서 취소하고, 콜백 실행 시 해당 entry가 현재 `_entry`인지 확인한다. 이미 제거된 entry에는 `remove()`를 다시 호출하지 않고 이전 세대의 콜백이 새 큐를 진행하지 못하게 식별자도 함께 관리한다.
- 오버레이 스낵바가 스크린 리더에 자동 안내되지 않음 → 메시지 컨테이너를 `Semantics(container: true, liveRegion: true, label: message)`로 감싸고 중복 읽기를 방지한다. 필요하다면 접근성 사용 중 표시 시간과 명시적 닫기 동작도 함께 제공한다.
- 일괄 연결 컨트롤이 한 줄 고정이라 작은 폭·큰 글자에서 넘침 → `Wrap`을 사용하거나 "즉시 저장" 토글과 진행 버튼을 별도 행으로 나눠 각 컨트롤이 텍스트 배율에 따라 재배치되게 한다.
