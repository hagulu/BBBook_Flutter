# 리뷰 결과

## 요약
- 메모 전체 삭제 흐름과 정적 분석은 정상이나, 새 사진 촬영·선택 경로가 저장 계층의 파일 규격과 맞지 않아 일반 사진을 저장하지 못할 수 있다.

## 문제점
- [문제][높음] `memo_photo_camera_screen.dart:102-106, 168`은 카메라를 `ResolutionPreset.high`로 촬영하고 갤러리 원본도 크기·품질·형식 변환 없이 그대로 반환한다. 반면 `book_memo_repository.dart:776-791`은 JPG/JPEG/PNG/WebP이면서 5MB 이하인 파일만 허용한다. 따라서 5MB를 넘는 고해상도 사진이나 HEIC 같은 기기 기본 형식은 편집 화면에서 정상 미리보기까지 된 뒤 저장 시 거절된다. 기존 갤러리 선택 코드에 있던 `imageQuality: 85`, `maxWidth: 1600` 제한도 이번 변경에서 사라졌고, 저장 화면은 구체적인 원인 대신 “메모 조각을 저장하지 못했습니다”만 표시해 사용자가 복구 방법을 알기 어렵다.
- [문제][낮음] `memo_photo_camera_screen.dart:170-195`는 갤러리 선택 성공 후 `Navigator.pop()`을 호출하고도 `finally`에서 `_isPickingImage`를 해제한 다음, 생명주기 전환 때 해제된 카메라를 다시 초기화한다. 이미 닫히는 라우트가 카메라 네이티브 리소스를 다시 획득하려 하므로 불필요한 초기화·해제가 발생하고, 빠르게 다음 촬영 화면을 열 때 카메라 리소스 경합 가능성을 만든다. 같은 역할의 OCR 촬영 화면은 성공 경로에서 재초기화를 건너뛰도록 처리되어 있다.

## 개선 제안
- 사진 입력과 저장 규격 불일치 → 촬영·갤러리 선택 결과를 반환하기 전에 서버 허용 형식으로 변환하고 5MB 이하가 되도록 리사이즈/압축한다. 최소한 갤러리 선택에는 기존 `maxWidth`·`imageQuality` 제한을 복원하고, 저장 실패 시 파일 크기·형식 오류 메시지를 사용자에게 전달한다.
- 닫히는 촬영 화면의 카메라 재초기화 → 갤러리 선택 성공 여부를 별도로 기록해 취소·실패한 경우에만 `_initializeCamera()`를 호출한다. OCR 촬영 화면의 `temporaryPath == null` 조건과 같은 형태로 성공 경로를 제외할 수 있다.
