# 리뷰 결과

## 요약
- `naver_login_flutter` 4.0.0 이관으로 이전 리뷰(`20260914-170049`)의 3건은 모두 해소됐고, 남은 문제는 앱 재시작 후 네이버 SDK 로그아웃이 실행되지 않는 점과 로깅·로딩 피드백·텍스트 배율 관련 3건입니다. `flutter analyze`와 `flutter build bundle`은 통과했습니다.

## 이전 리뷰 항목 종결
- [P1 해소] Android Access Token 누락 — 4.0.0의 Android `logIn()`은 `getCurrentAccount(result, includeToken = true)`로 토큰을 결과에 포함하며(`FlutterNaverLoginPlugin.kt:248`), 앱은 추가로 `getCurrentAccessToken()`도 호출하므로 양쪽 경로 모두 토큰을 확보합니다.
- [P2 해소] iOS 리다이렉트 콜백 — 플러그인이 `registrar.addApplicationDelegate` / `addSceneDelegate`로 직접 등록해 `application(_:open:)`과 `scene(_:openURLContexts:)`를 처리합니다. 프로젝트의 `ios/Runner/SceneDelegate.swift`가 `FlutterSceneDelegate`를 상속하고 있어 콜백 경로가 연결됩니다. `AppDelegate.swift` 수정은 불필요합니다.
- [P2 해소] Client Secret 로그 노출 — 4.0.0은 `clientSecret.masked()`로만 출력하고 로그 자체도 `com.naver.sdk.logEnabled` 메타데이터로 게이팅됩니다. 매니페스트에 `logEnabled=false`가 설정되어 있습니다.

## 문제점
- [P1] 앱 재시작 후 네이버 SDK 로그아웃이 실행되지 않음 — `lib/features/auth/data/social_auth_service.dart:117`: `signOutNaver()`가 `if (!_naverUsed) return;`로 시작하는데, `_naverUsed`는 메모리 전용 플래그이고 `socialAuthServiceProvider`는 앱 수명 동안 유지되는 단순 `Provider`입니다. 네이버로 로그인 → 앱 종료 → 세션 복원 → 로그아웃(또는 401 재시도 실패로 인한 `clearLocalSession()`) 경로에서는 `_naverUsed`가 `false`라 `FlutterNaverLogin.logOut()`이 한 번도 호출되지 않습니다. 401 강제 로그아웃은 앱 재시작 직후 refresh 실패 시 가장 잘 발생하는 경로입니다.
  - 이 가드는 필요하지도 않습니다. iOS는 플러그인 `register()`에서 `NidOAuth.shared.initialize(...)`를, Android는 엔진 attach 시 매니페스트 메타데이터를 읽어 `NidOAuth.initialize(...)`를 무조건 호출합니다. 즉 로그인 여부와 무관하게 SDK는 이미 초기화된 상태이므로, `signOutGoogle()`의 `_googleInitialized`와 달리 이 플래그는 호출을 막기만 합니다.
- [P2] 새 코드만 로깅 방식이 다름 — `lib/features/auth/data/social_auth_service.dart:98,104,111,122`: 코드베이스는 `developer.log`를 161곳에서 쓰는데 네이버 코드만 `debugPrint`를 씁니다(전체 `debugPrint` 7건 중 4건이 이번 변경분). 작업명도 기존은 한국어(`[소셜 로그인]`, `[테마 조회]`)인데 `[naver_login]`/`[naver_logout]`만 영문입니다. 또한 `auth_notifier._login`이 이미 `[소셜 로그인] provider=naver result=FAIL`을 남기므로 실패 로그가 두 계층에서 중복됩니다.
- [P2] Apple 버튼만 로딩 표시가 사라짐 — `lib/features/auth/screens/onboarding_screen.dart:207`: `SignInWithAppleButton`으로 교체되면서 `isLoading` 전달이 없어졌습니다. `_handleAppleLogin`이 여전히 설정하는 `_LoadingProvider.apple` 상태는 어디에서도 렌더링되지 않아, Apple 로그인 중에는 버튼이 비활성화만 될 뿐 진행 중이라는 피드백이 없습니다. 나머지 3개 버튼은 스피너를 표시하므로 피드백이 비대칭입니다.
- [P3] 텍스트 배율 확대 시 라벨 오버플로우 — `lib/features/auth/widgets/social_login_button.dart:58,80`: 버튼 높이가 `48`로 고정된 상태에서 라벨은 `fontSize: 15` bold이고 `maxLines`/`overflow` 지정이 없습니다. OS 텍스트 크기를 크게 설정하면 고정 높이 안에서 텍스트가 잘리거나 오버플로우합니다. 이 코드베이스는 다른 화면(`profile_screen.dart:406`, `book_detail_screen.dart:440` 등)에서 `MediaQuery.textScalerOf`로 배율을 반영하고 있어 기준이 어긋납니다.
- [P3] 카카오·네이버 심볼이 공식 배포 에셋이 아님 — `assets/icon/social/kakao.svg`, `assets/icon/social/naver.svg`: `google.svg`는 공식 4색 G 로고 경로인 반면, 두 파일은 단일 `path`로 단순화해 직접 그린 도형입니다(네이버는 직선 N, 카카오는 일반 말풍선). 코드 주석은 각 사의 로그인 디자인 가이드를 근거로 색상·여백·radius를 맞춰 놓았는데 심볼만 자체 제작이라 근거가 어긋납니다. 각 사가 배포하는 공식 로그인 버튼 에셋 사용 요건은 별도 확인이 필요합니다.

## 개선 제안
- 네이버 로그아웃 미실행 → `_naverUsed` 플래그와 조기 반환을 제거하고, `signOutKakao()`처럼 `try/catch`로 감싼 무조건 호출로 바꿉니다. SDK가 로그인 상태가 아닐 때의 예외는 기존 `catch`가 이미 흡수합니다.
- 로깅 불일치 → `debugPrint`를 `developer.log`로 바꾸고 작업명을 `[소셜 로그인]` / `[소셜 로그아웃]`으로 통일하며, `provider=naver`를 key=value로 넘깁니다. `auth_notifier`와 겹치는 실패 로그는 한쪽만 남깁니다(SDK 단 원인은 `reason=`으로 구분).
- Apple 로딩 표시 누락 → `SignInWithAppleButton`을 `AppLoadingOverlay`로 감싸거나 `_loading == _LoadingProvider.apple`일 때 스피너를 겹쳐, 나머지 버튼과 동일한 피드백을 줍니다. 로딩 표시를 하지 않기로 했다면 `_handleAppleLogin`에서 `_LoadingProvider.apple` 설정도 정리해 사용되지 않는 상태를 남기지 않습니다.
- 텍스트 배율 오버플로우 → 높이를 `MediaQuery.textScalerOf(context).scale(48)`로 확장하거나 `ConstrainedBox(minHeight: 48)`로 바꾸고, 라벨에 `maxLines: 1`과 `overflow: TextOverflow.ellipsis`를 지정합니다.
- 브랜드 심볼 → 카카오/네이버 개발자센터에서 배포하는 공식 로그인 버튼 심볼 파일로 교체하고, 교체가 어려우면 가이드 준수를 단정하는 주석 표현을 조정합니다.

정적 분석만 수행했습니다. 프로젝트 지침에 따라 앱 실행과 테스트는 하지 않아 네이티브 네이버 로그인 왕복(네이버 앱 설치/미설치, 취소, 로그아웃 후 재로그인)은 검증되지 않았습니다. `flutter analyze` 통과와 `flutter build bundle` 성공은 컴파일과 에셋 등록만 증명하며, 위 문제점 중 어느 것도 두 검증으로는 드러나지 않습니다.
