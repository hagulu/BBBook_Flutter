# 리뷰 결과

## 요약
- 새 일반 공지 배지·중요 공지 팝업 변경분에서 P2 문제 3건을 확인했으며, `flutter analyze`는 통과했다.
- 범위: 현재 미커밋 변경사항과 새 공지 모델·저장소·서비스·위젯·테스트 코드, 기존 목록 화면과 공통 시트 구성. API 계약은 `../../api-doc/api-notices-*.md`로 확인했다.
- 검증: 정적 코드 검토와 `flutter analyze`(`No issues found!`). 프로젝트 지침에 따라 테스트와 앱 실행은 수행하지 않았다. 아래 재현 조건은 코드 흐름과 레이아웃 제약을 기준으로 확인한 것이며, 기기에서 실행해 재현하지는 않았다.

## 문제점
- [P2][표시하지 않은 공지가 확인 처리됨] `lib/features/notices/providers/notices_providers.dart:79–89` — 목록 응답을 받은 뒤 별도 `/api/notices/latest` 요청의 id를 저장한다. 예를 들어 목록에는 id 50까지 내려왔는데 두 요청 사이에 id 51이 등록되면, 화면에는 50까지 표시하면서 51까지 확인한 것으로 저장해 새 공지 배지가 사라진다. 또한 목록을 표시하기 전에 `_markSeen()`을 실행하고 화면 이탈 시 작업 중단 여부를 확인하지 않아, 로딩 중 뒤로 간 경우에도 확인 id를 저장할 수 있다. 사용자가 확인하지 못한 공지의 배지가 다음 진입에서도 숨겨지는 문제다.
- [P2][큰 글씨·긴 제목에서 중요 공지 시트가 넘침] `lib/features/notices/widgets/important_notice_dialog.dart:89–95` — 본문 최대 높이는 제목·버튼 등의 실제 높이 대신 고정값 210을 빼서 계산하고, 남은 공간이 작아도 본문 높이를 최소 160으로 강제한다. 제목은 줄 수 제한 없이 늘어나고 바깥 `Column`은 스크롤되지 않으므로, 큰 글씨에서 여러 줄 제목과 긴 본문이 함께 표시되거나 화면 높이가 작으면 전체 높이가 시트 제약을 초과한다. 본문만 스크롤할 수 있어 아래의 `확인`·`그만 보기` 버튼이 잘리는 경우에도 접근할 수 없다.
- [P2][배지 조회 지연이 정상 목록 표시를 막음] `lib/features/notices/providers/notices_providers.dart:67–75` — 첫 페이지를 정상 수신해도 `await _markSeen()`이 끝나야 목록 상태를 반환한다. 부가 요청인 `/api/notices/latest`가 느리거나 응답하지 않으면 이미 받은 목록 대신 로딩 화면을 계속 표시한다. 공통 Dio 설정의 수신 타임아웃은 10초이며, 예외를 무시하는 처리는 이 기다림이 끝난 뒤에만 적용된다.

## 개선 제안
- 표시하지 않은 공지의 확인 처리 → 성공적으로 표시한 목록에 포함된 일반 공지를 기준으로 확인 id를 결정하고, 화면 이탈·provider 폐기 여부를 확인한 뒤 저장한다. 목록 조회 이후 등록된 공지는 다음 조회에서 확인하기 전까지 배지를 유지한다.
- 중요 공지 시트의 높이 초과 → 실제 시트 제약 안에서 제목·버튼 영역을 배치하고 본문에 남은 공간을 할당한다. 공간이 부족할 때 160의 최소 높이가 제약을 넘지 않도록 하며, 큰 글씨와 긴 제목에서도 버튼에 접근할 수 있는 스크롤 구성을 적용한다.
- 배지 요청에 종속된 목록 로딩 → 목록 요청 성공 즉시 목록 상태를 제공하고, 확인 처리와 배지 갱신은 별도 후처리로 실행한다. 후처리에도 화면 생명주기 확인과 오류 처리를 유지한다.
