# 리뷰 결과

## 요약
독후감·토론·공개 독후감 지면을 카드형에서 여백·구분선 기반의 읽기 지면으로 바꾼 UI 변경으로, 대부분은 안전하지만 독후감 편집기의 슬리버 전환은 debug 빌드에서 화면을 여는 즉시 예외가 발생하는 구조이고 공통 위젯 변경 일부가 이번 범위 밖 화면으로 새어 나갔다.

## 문제점

- [치명] `book_reflection_editor_screen.dart:640` — `SliverFillRemaining(hasScrollBody: false)` 바로 아래에 `LayoutBuilder`(`:644`)가 들어갔다. `RenderSliverFillRemaining.performLayout`은 자식의 `getMaxIntrinsicHeight`를 호출하는데(`flutter/packages/flutter/lib/src/rendering/sliver_fill.dart:201`), 사이에 있는 `Padding`/`Align`/`ConstrainedBox`는 그 호출을 그대로 자식에게 넘기고 `_RenderLayoutBuilder`는 intrinsic 계산을 거부한다(`layout_builder.dart:414`). 결과적으로 **debug 빌드에서 독후감 작성/수정 화면을 열면 `LayoutBuilder does not support returning intrinsic dimensions.` 예외로 즉시 실패**한다. release 빌드에서는 assert가 제거되어 0을 반환하므로 본문 높이가 "남은 뷰포트 높이"로 고정되고, 그보다 긴 독후감은 잘린 채 스크롤되지 않는다. `flutter analyze`로는 잡히지 않는다.
- [중대] `book_reflection_editor_screen.dart:617` — 위와 같은 슬리버 전환의 두 번째 증상으로, `SliverAppBar(pinned: false)`의 `actions`에 저장 버튼이 들어가 있어 본문을 조금만 내려도 저장·뒤로 버튼이 함께 화면 밖으로 사라진다. 편집기는 입력 시 커서를 따라 자동 스크롤하므로 글이 길어질수록 저장하려면 매번 맨 위까지 올라와야 한다. 같은 성격의 작성 화면인 `discussion_form_screen.dart:161`은 기존 `AppBar`를 유지해 저장 버튼이 고정돼 있어, 두 작성 화면의 동작이 서로 어긋난다.
- [중] `community_content.dart:301` — `CommunityContentEmptyList`에 `horizontal: 24` 패딩이 추가됐는데, 이 위젯의 유일한 사용처인 `book_review_list_screen.dart:232`는 이번 변경 대상이 아니고 목록 본문은 여전히 좌우 16(`:244`)이다. 같은 화면에서 빈 상태와 목록 상태의 좌우 여백이 24/16으로 어긋난다.
- [중] `community_content.dart:286` — 같은 위젯에 추가된 `header` 파라미터를 넘기는 곳이 없다. 헤더가 필요했던 `public_reflection_list_screen.dart:126`은 이 위젯을 쓰지 않고 빈 상태를 `SliverFillRemaining`으로 새로 구현했다(`:131`). 공통 위젯에 죽은 파라미터만 남고 빈 상태 구현은 두 벌이 됐다.
- [중] `community_content.dart:60` — `CommunityContentCard`가 더 이상 테두리·표면을 그리지 않는데 `borderRadius`(기본값 0) 파라미터가 남아 있고, 넘기는 호출부도 사라졌다. 그런데도 `Material(color: Colors.transparent, clipBehavior: Clip.antiAlias, borderRadius: 0)`(`:81`)은 유지돼, 목록의 모든 행마다 아무것도 자르지 않는 클립 레이어가 생긴다. 이름(`Card`)과 실제 역할(구분선 기반 행)도 어긋난다.
- [소] `discussion_detail_screen.dart:843` — 항목 사이에만 구분선을 넣으려고 `for (final answer in ...)`을 인덱스 루프로 바꾸면서 `state.items[answerIndex]`가 한 블록에서 8번 반복된다. 구분선 조건만 필요한 변경인데 본문 가독성이 함께 나빠졌다.
- [소] `discussion_detail_screen.dart:160` — 자유 답변 버튼 문구는 '나의 생각 남기기', 목록 제목은 '함께 나눈 생각'으로 바뀌었는데, 실제로 열리는 시트의 힌트만 이전 문구인 '답변을 작성해보세요...'로 남아 있다.
- [소] `community_content.dart:156`, `:501` — `CommunityAuthorRow`의 inline 레이아웃이 `Row`에서 `Wrap`으로 바뀌고 작성일 글자가 11→12로, `CommunityLikeInline`의 터치 영역 패딩이 6/8→12/12로 커졌다. 이 두 위젯은 이번 diff에 없는 `book_detail/screens/widgets/review_item.dart:90,186`과 `book_community/screens/widgets/book_community_preview_section.dart:382`도 함께 쓴다. 두 화면 모두 높이 고정 컨테이너가 아니라 레이아웃이 깨지지는 않지만, 독자평 지면의 간격이 의도치 않게 같이 바뀐다.

## 개선 제안

- 편집기의 intrinsic 예외 → 편집기를 슬리버로 바꾸기 전 구조(일반 `AppBar` + `SingleChildScrollView` + 스크롤뷰 **바깥**의 `LayoutBuilder`)로 되돌리고, 이번 변경 중 시각적인 부분(좌우 24 여백, 제목 22/타이포, 구분선 간격, 본문 행간 1.8, 책 제목 라벨)만 그대로 남긴다. 작성 화면은 앱바가 스크롤되어 사라질 이유가 없고, `discussion_form_screen`과 구조도 다시 맞는다.
  - 슬리버 구조를 꼭 유지해야 한다면 `LayoutBuilder`와 그 안의 `ConstrainedBox(minHeight:)`를 삭제한다. `SliverFillRemaining(hasScrollBody: false)`가 이미 "남은 뷰포트 높이 이상"의 tight 제약을 자식에게 주므로 최소 높이 확보 용도로는 중복이고, flutter_quill의 에디터 렌더 객체는 intrinsic을 구현하고 있어(`flutter_quill/lib/src/editor/editor.dart:1802`) 본문이 길어지면 그만큼 스크롤 범위가 늘어난다. 다만 이 경로는 레이아웃마다 문서 전체를 다시 측정하므로 긴 독후감에서 입력 지연이 생길 수 있어 실기기 확인이 필요하다.
- 저장 버튼이 사라지는 문제 → 위 되돌림으로 함께 해결된다. 슬리버를 유지한다면 최소한 `pinned: true`로 두거나 저장을 하단 툴바 쪽 고정 액션으로 옮긴다.
- 빈 상태 좌우 여백 어긋남 → `CommunityContentEmptyList`에 패딩을 고정하지 말고 호출부가 목록과 같은 값을 넘기도록 `padding` 파라미터로 받거나, `book_review_list_screen`의 목록 패딩도 24로 함께 맞춘다.
- 죽은 `header` 파라미터와 중복된 빈 상태 → `public_reflection_list_screen`의 빈 상태를 `CommunityContentEmptyList(header: _BookTitleLabel(...))`로 되돌려 `header`를 실제로 쓰거나, 슬리버 기반 빈 상태를 계속 쓸 거면 `header` 파라미터를 삭제한다.
- `CommunityContentCard` → 더 이상 카드가 아니므로 `borderRadius` 파라미터와 `clipBehavior: Clip.antiAlias`를 제거하고(`Material`은 잉크 표면용으로만 남긴다), 이름도 역할에 맞게 `CommunityContentRow` 등으로 정리한다.
- 답변 목록 인덱스 루프 → `for (final (answerIndex, answer) in state.items.indexed)`를 쓰면 구분선 조건(`answerIndex < state.items.length - 1`)은 유지하면서 본문은 이전처럼 `answer`로 읽을 수 있다.
- 시트 힌트 문구 → `discussion_detail_screen.dart:160`의 힌트를 새 카피 톤('나의 생각', '함께 나눈 생각')에 맞춰 통일한다.
- 공통 위젯 변경 범위 → `CommunityAuthorRow`/`CommunityLikeInline` 변경이 독자평 지면에도 적용되는 것이 의도인지 확인하고, 의도라면 독자평 목록의 간격도 같은 기준으로 함께 점검한다.
