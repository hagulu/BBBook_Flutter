# 리뷰 결과

## 요약

- 현재 프로젝트의 미커밋 변경 6개 파일에서 진행 기록의 단위 처리와 변경 확인 흐름에 영향을 주는 문제 3건을 확인했다.

## 문제점

- [P1][출처 미설정 책을 오디오북으로 바꿀 때 쪽수를 퍼센트로 남김] `lib/features/bookshelf/models/book_item.dart:132` — `sourceType == null`이면 `currentPage`를 무조건 유지한다. 출처를 고르기 전에도 책 기록 화면에서 쪽수 진행률을 입력할 수 있으므로, 80쪽 읽은 책을 처음 오디오북으로 지정하면 80%로 잘못 저장된다. 101쪽 이상이면 오디오북의 100 상한을 넘어서 기록 PATCH가 400으로 거부되고 변경이 동기화되지 않는다. `meta_dialogs.dart:235`도 초기 출처가 null이면 경고를 생략한다.
- [P2][총쪽수 축소 시 읽은 쪽수를 알리지 않고 변경] `lib/features/book_record/data/book_record_repository.dart:308` — 책 정보 수정에서 총쪽수를 현재 읽은 쪽수보다 작게 입력하면 `currentPage`를 새 총쪽수로 자동 덮어쓴다. 전자책 쪽수 입력도 같은 방식으로 저장되며 `meta_dialogs.dart:218`은 기존 입력 오류 표시를 제거했다. 사용자는 총쪽수를 고치다가 읽은 위치까지 바뀐 사실을 저장 전에 알 수 없다.
- [P3][변경 확인을 취소해도 출처 선택이 남음] `lib/features/book_record/screens/widgets/meta_dialogs.dart:273` — 종이책 선택 시 `_source`를 먼저 바꾸고 `_save()`에서 확인을 받는다. 오디오북에서 종이책으로 바꾸는 경고를 취소하면 시트에는 종이책이 계속 선택된 채 남지만 저장은 되지 않는다. 종이책에는 별도 저장 버튼도 없어 선택 표시와 실제 기록 상태가 어긋난다.

## 개선 제안

- 출처 미설정 상태의 단위 오인 → 기존 쪽수 기록이 있는 책을 처음 오디오북으로 지정할 때도 초기화하고, 다이얼로그에서 같은 조건으로 확인을 받는다. 처음 전자책으로 지정하며 총쪽수를 낮추는 경우도 새 상한에 맞게 처리한다.
- 진행 기록의 묵시적 변경 → 저장 전에 기존 읽은 쪽수와 변경될 값을 보여주고 확인을 받은 뒤 적용한다.
- 확인 취소 후 선택 표시 불일치 → 확인이 끝난 뒤 선택을 반영하거나 취소 시 이전 선택으로 되돌린다.

검증: `flutter analyze` 통과. 프로젝트 지침에 따라 앱과 테스트는 실행하지 않았다.
