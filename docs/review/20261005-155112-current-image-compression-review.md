## 문제점

- [P2][Android에서 HEIC 메모 사진의 갤러리 선택이 실패함] `lib/shared/image/services/image_gallery_picker.dart:16` — 새 호출은 `imageQuality`와 크기 옵션을 모두 생략한다. 설치된 Android 구현은 이 조건에서 네이티브 변환 없이 원본 파일을 반환한다. 이어서 호출되는 `ImageCompressor`의 `img.decodeImage`에는 HEIC/HEIF 디코더가 없으므로, Android 갤러리가 HEIC 원본을 전달하면 정상 사진도 압축에 실패한다. 메모 사진 화면은 오류 팝업만 표시하고 이미지 편집기로 진행하지 못한다. 기존 메모 갤러리 경로는 `imageQuality: 85`와 `maxWidth: 1600`으로 플랫폼 디코더가 읽을 수 있는 HEIC를 JPEG 바이트로 변환한 뒤 편집기에 전달했다. 따라서 그 조건의 사진 첨부가 회귀한다. iOS의 설치된 picker는 자체적으로 JPEG 변환을 수행하므로 이 문제를 iOS 전체에 적용하지 않는다.

- [P2][고해상도 원본을 전부 디코딩·복사한 뒤에야 크기를 줄임] `lib/core/image/image_compressor.dart:58` — 갤러리에서 받은 원본 전체를 `decodeImage`로 디코딩하고, `bakeOrientation`으로 원본 크기의 픽셀 버퍼를 복사한 다음 1600px 제한을 적용한다. 설치된 `image` 패키지의 `bakeOrientation`은 회전이 필요 없는 사진도 먼저 `Image.from`으로 복사하며, JPEG 디코더도 원본 크기에 비례하는 DCT·성분 버퍼를 할당한다. 예를 들어 8000×6000 RGB 사진은 픽셀 버퍼 하나만 약 144MB이고, 회전 처리의 복사본과 디코더 버퍼를 더하면 수백 MB를 사용할 수 있다. 이전 메모 갤러리 경로의 크기 제한이 제거되어 이런 원본이 그대로 Dart 디코더에 들어온다. isolate는 작업 스레드를 옮길 뿐 앱 프로세스의 메모리 사용량을 제한하지 않아, 메모리가 부족한 기기에서는 이미지 선택 중 앱이 종료될 위험이 있다. 출력의 1600px·5MB 제한은 이 디코딩 단계의 메모리를 보호하지 않는다.

- [P3][메모 갤러리 사진을 저장할 때 JPEG 손실 압축이 반복됨] `lib/core/storage/local_image_store.dart:164` — 갤러리 선택은 이미 `bbbook_img_*.jpg`를 JPEG 85로 생성하지만, 메모 사진은 반드시 공용 이미지 편집기를 거쳐 `edited_*.jpg` 경로로 전달된다. 편집 없이 완료하면 라이브러리는 형식·크기 조건을 충족하는 원본 JPEG 바이트를 그대로 반환한다. 그러나 앱이 이를 `edited_` 접두어로 저장하여 처리 완료 표지가 사라지고, 저장소는 이미 정책을 충족한 사진도 JPEG 85로 다시 인코딩한다. 실제 크롭·그리기 등을 적용하면 갤러리 압축 → 편집기 JPEG 85 출력 → 저장소 JPEG 85 출력으로 세 단계의 손실 압축이 수행된다. 기존 경로보다 저장 시 손실 압축이 한 번 추가되어 책 문장 사진의 작은 글자·윤곽에 불필요한 화질 손실이 누적되고, 저장 시 디코딩·인코딩 비용도 추가된다. 갤러리 결과의 접두어만 검사하는 현재 방식으로는 실제 메모 저장 경로의 재압축을 막지 못한다.

## 개선 제안

- Android HEIC 원본 처리 실패 → 플랫폼에서 지원하는 원본 형식을 JPEG로 정규화하는 경로를 유지하거나, 해당 형식을 지원하는 디코더를 사용한 뒤 공통 크기·품질 정책을 적용한다. 지원되지 않는 디코딩 형식과 실제 손상 파일도 구분해 안내한다.
- 전체 원본 디코딩에 따른 메모리 급증 → 디코딩 전에 이미지 헤더의 크기를 확인하고, 큰 원본은 네이티브 축소 디코딩 등으로 작업 크기를 제한한 뒤 Dart 후처리로 전달한다. 순수 Dart 전체 디코딩을 유지해야 한다면 입력 픽셀 수 상한을 둔다. 압축 후의 파일 용량 검사만으로 대체하지 않는다.
- 편집·저장 단계의 반복 JPEG 인코딩 → 최종 JPEG 정책 적용 지점을 정하고, 그 전의 편집 중간 결과는 추가 손실을 피하도록 전달한다. 편집 결과가 이미 긴 변·품질 정책을 충족하는 경우 저장소는 처리 정보를 받아 복사하도록 한다. 접두어 변경만으로 정책 충족 여부를 간주하지 않는다.
