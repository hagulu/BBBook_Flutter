# 리뷰 결과

## 요약
공용 사진 카메라는 생명주기·이전 화면 해제·촬영 방향을 명시적으로 처리합니다. 현재 코드에서 별도 확정 결함을 추가하지 않았습니다. 바코드 카메라는 구현이 달라 별도 문서로 분리했습니다.

## 확인 범위
카메라 최초 권한, 거부와 재시도, 초기화 중 inactive, 홈/잠금 후 복귀, 화면 닫자마자 재진입, 촬영 중 닫기, 갤러리 전환/취소, 기기 회전, 사진 편집/저장 실패, OCR 캡처→크롭→인식→선택 흐름을 검토했습니다.

## 문제점

정적 검토만으로 일반 사진 카메라의 추가 결함을 확정하지 않았습니다. 기기별 카메라 미리보기 비율이나 회전 좌표가 실제로 올바른지는 코드만으로 ‘문제 없음’을 보증할 수 없습니다.

바코드의 생명주기, 모달 중 인식, 인식 범위, 빠른 등록 정보 누락은 [바코드 리뷰](./20261028-124818-barcode-scan.md)의 DEV-01~04입니다.

## 개선 제안

현재 공용 카메라 직렬화 구조를 다시 작성하기보다 아래 일반 시나리오를 실기기에서 확인하고 재현된 문제만 좁게 수정하는 것이 적절합니다. 모든 작성 화면의 프로세스 종료 복구나 새로운 백그라운드 서비스 도입을 요구하지 않습니다.

## 확인된 보호 장치

- [lib/shared/image/screens/shared_camera_screen.dart:126](/Users/hagulu/develop/service/BBBook/project/app/bbbook/lib/shared/image/screens/shared_camera_screen.dart:126): 화면 인스턴스와 무관한 카메라 생성/해제 체인과 소유자 확인으로 재진입 시 해제 경합을 줄입니다.
- 초기화 세대로 오래된 초기화 결과를 버립니다. 권한 다이얼로그로 inactive가 된 초기화는 무조건 재시작하지 않습니다.
- inactive/paused 등에서는 카메라를 해제하고 resumed에서 다시 획득합니다. 갤러리 처리 중에는 복귀 초기화를 구분합니다.
- 센서 방향 잠금은 별도 큐로 처리하며, 앱 UI는 세로 방향으로 잠급니다. 회전은 촬영 방향과 컨트롤에 반영합니다.
- 촬영·갤러리 처리 중 뒤로 가기를 막고 중복 촬영을 방지합니다. 초기화·촬영·갤러리 예외는 안내하며 재시도할 수 있습니다.
- 일반 이미지는 1600px JPEG 정책을 적용하고 EXIF 회전을 픽셀에 반영합니다. OCR은 해상도 보존 정책이 별도입니다.
- 이미지 에디터는 완료와 닫기 콜백의 중복 pop을 막습니다. OCR recognizer와 codec/image 자원은 finally에서 해제합니다.

## 실제 기기 확인 항목

| 상황 | 기대 결과 |
|---|---|
| 첫 권한 허용·거부·설정에서 재허용 | 오류/재시도/복귀 경로가 종료되지 않고 동작 |
| 초기화 중 홈 → 복귀, 잠금 → 해제 | 검은 화면이나 중복 카메라가 남지 않음 |
| 세로·좌우 가로로 기울인 촬영 | 저장된 사진 방향과 OCR 단어 위치가 일치 |
| 촬영 직후 알림/전화 등 inactive | 오류 안내 후 다시 촬영 가능 |
| 갤러리 선택 취소와 편집 취소 | 이전 화면과 카메라 상태가 맞음 |
| 촬영 화면 닫자마자 재진입 | 이전 dispose가 새 미리보기를 끊지 않음 |
| 일반 휴대폰 고해상도 사진, HEIC | 편집 성공 또는 이해 가능한 실패 안내 |
| 큰 글자·작은 화면·키보드 | 완료/닫기/선택 버튼에 접근 가능 |

Android가 갤러리 선택 중 Activity/프로세스를 재생성하는 경우의 lost-data 복구는 현재 별도 경로가 보이지 않습니다. 다만 원래 편집 대상까지 자동 복원하는 설계는 범위가 커, 이번에는 확정 결함이나 필수 개편으로 집계하지 않고 실기기 확인 범위로 남겼습니다.
