# 리뷰 결과

## 요약
공개 독후감·공개 책장·신고·공지·업데이트 흐름에서는 이번 범위의 독립 결함을 추가하지 않았습니다. 이미 다른 문서에 있는 네트워크 재시도와 모달 경계를 함께 확인해야 합니다.

## 확인 범위
공개 독후감 목록/리더/공감, 다른 사용자 완독 책장·403 비공개 안내·작성자 시트·사용자 신고, 내 콘텐츠 목록, 일반 공지 목록·상세·다음 페이지 재시도·배지, 중요 공지 중복 표시, 권장/강제 업데이트와 앱 복귀 재확인을 검토했습니다.

## 문제점

- 공개/비공개 설정이 실제 서버와 다를 수 있는 개인 독후감 문제는 [INIT-01](../02-sync/20261028-124818-initial-download.md)과 [REF-01](../04-records/20261028-124818-reflections-editor-visibility.md)입니다. 공개 조회 서비스의 별도 결함으로 중복 집계하지 않았습니다.
- 공통 ApiClient를 사용하는 공개 조회의 즉시 재시도는 [NET-01](../08-common/20261028-124818-network-navigation-security.md)의 영향을 받습니다. 공지·앱 버전 조회는 별도 Dio를 사용하므로 같은 제한이 적용되지 않습니다.

## 개선 제안

위 원인을 해당 소유 기능에서 먼저 고치고, 공개 목록·리더에서 실제 노출과 배지 숫자가 일치하는지 확인합니다. 서버가 인가하는 공개 여부를 클라이언트에서 추측해 대체하거나 목록 응답 전체에 추가 강제 조회를 넣는 개편은 요구하지 않습니다.

## 확인된 보호 장치

- 공개 독후감 목록은 숨김 항목을 제거하고 잘못된 반복 커서에 대한 방어가 있습니다. 상세 노출 여부는 상세 API의 인가 계약을 따릅니다.
- 공개 책장의 403을 일반 네트워크 실패와 구분하고, 본인 신고 진입을 제한합니다.
- 내 독후감 목록은 로컬 소유자와 숨김 상태를 반영합니다. 다른 내 콘텐츠 목록은 서버 API를 사용합니다.
- 공지 목록의 추가 페이지 오류는 기존 목록을 보존하고 별도 재시도 상태를 표시합니다. 공지 상세 404는 없는 공지 안내로 구분합니다.
- 중요 공지 확인 중 중복 표시 가드와 건별 그만 보기 저장이 있습니다.
- 강제 업데이트는 기존 child 상태를 유지하면서 입력/뒤로 가기를 차단하고, 이미 강제 상태일 때 정책 재조회 실패로 차단을 풀지 않습니다. 스토어 열기 실패를 안내합니다.

## 실제 기기 확인 항목

일반적인 큰 글자 배율, 좁은 화면의 공지/선택지/페이지 버튼, 스크린 리더의 공감·신고 동작, 스토어에서 돌아온 뒤 강제 정책 재확인, 중요 공지가 카메라/작성 화면 위에 올라올 때 상호작용을 확인합니다. 렌더링과 네이티브 스토어 실행은 이번에 수행하지 않았습니다.
