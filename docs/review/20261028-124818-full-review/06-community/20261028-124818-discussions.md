# 리뷰 결과

## 요약
답변 제출 중복 방지와 등록 후 조회 실패 구분은 있으나, 전송 중 화면 닫기와 목록 갱신 경쟁에 P2 2건이 있습니다.

## 확인 범위
열린/전체 목록, 자유/선택지 토론 작성·수정, 선택지 append-only, 마감·닫기·재오픈·삭제, 답변 작성·수정·삭제·페이지 이동, 공감·신고를 확인했습니다.

## 문제점

### [COMM-01][P2] 토론·답변 전송 중 뒤로 가기나 시트 닫기로 처리 결과를 잃을 수 있음

- 근거: [lib/features/discussion/screens/discussion_form_screen.dart:127](/Users/hagulu/develop/service/BBBook/project/app/bbbook/lib/features/discussion/screens/discussion_form_screen.dart:127)은 `_isSaving`으로 저장 버튼만 막고, [lib/features/discussion/screens/discussion_form_screen.dart:180](/Users/hagulu/develop/service/BBBook/project/app/bbbook/lib/features/discussion/screens/discussion_form_screen.dart:180)의 화면에는 저장 중 pop 차단이 없습니다. [lib/features/discussion/screens/widgets/discussion_answer_composer.dart:21](/Users/hagulu/develop/service/BBBook/project/app/bbbook/lib/features/discussion/screens/widgets/discussion_answer_composer.dart:21)도 기본 dismiss/drag 가능한 시트이며 `_isSubmitting`일 때 닫기를 막지 않습니다.
- 일반 재현: 느린 통신에서 등록을 누르고 앱바 뒤로 가기·시스템 뒤로 가기 또는 답변 시트 아래로 드래그를 합니다.
- 영향: 입력과 결과 안내가 사라지지만 이미 시작된 서버 쓰기는 계속됩니다. 사용자는 취소됐다고 생각하거나 재작성해 중복 토론·답변을 등록할 수 있습니다. `_isSubmitting`은 같은 열린 시트 안의 연타만 방지합니다.

### [COMM-02][P2] 새로고침 이전의 다음 페이지 응답이 갱신된 토론 목록에 섞일 수 있음

- 근거: [lib/features/discussion/providers/discussion_providers.dart:77](/Users/hagulu/develop/service/BBBook/project/app/bbbook/lib/features/discussion/providers/discussion_providers.dart:77)의 `loadMore()`는 완료 시점의 최신 state에 이전 커서 결과를 붙입니다. [lib/features/discussion/providers/discussion_providers.dart:115](/Users/hagulu/develop/service/BBBook/project/app/bbbook/lib/features/discussion/providers/discussion_providers.dart:115)의 `refresh()`와 공유하는 요청 세대/락이 없습니다.
- 조건: 다음 페이지 조회 중 당겨서 새로고침하거나 토론 상세의 수정·닫기 후 목록 재조회가 겹칩니다.
- 영향: 새 필터 상태에서 빠져야 할 닫힌 토론이 다시 붙거나, 항목 중복·누락·스크롤 변화가 생길 수 있습니다. 리뷰 목록에 이미 있는 요청 세대 방어가 이 목록에는 없습니다.

## 개선 제안

- COMM-01: 전송 중에 한해 뒤로 가기·시트 dismiss를 막고 처리 중임을 안내합니다. 네트워크 전송이 시작된 뒤 ‘취소’를 서버 롤백으로 오해하게 만들지 않습니다. 기존 노트 AI 생성 화면의 PopScope와 같은 좁은 적용으로 충분합니다.
- COMM-02: refresh 시작 때 세대를 올리고 이전 loadMore 응답을 버립니다. 폐기된 요청의 loading 플래그도 함께 정리합니다. 전체 페이징 구조를 바꿀 필요는 없습니다.

## 확인된 보호 장치

답변 등록과 목록 조회 실패를 분리하고, 삭제 후 마지막 페이지 보정이 있습니다. 주제·답변 공감은 화면에서 진행 상태를 관리합니다. 선택지는 기존 항목을 바꾸지 못하게 검사하고 마감/닫기 변경 후 서버 상태를 다시 읽습니다. 답변 작성 시트는 실패 결과가 돌아오면 입력을 보존합니다.
