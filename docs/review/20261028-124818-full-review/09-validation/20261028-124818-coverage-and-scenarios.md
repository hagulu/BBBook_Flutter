## 문제점

이 문서는 실행 증거와 후속 확인 범위를 정리하는 문서이며, 다른 문서의 결함을 추가 건수로 중복 집계하지 않습니다. `flutter analyze` 통과는 비동기 순서·서버 식별자·실제 기기 동작의 정확성을 검증하지 않습니다.

## 개선 제안: 후속 검증 순서

| 우선 | 시나리오 | 확인할 결과 |
|---|---|---|
| 1 | 최초 다운로드한 공개 독후감 수정/삭제/비공개 | 동일 서버 ID에 반영되고 원래 공개 글이 남지 않음 |
| 1 | 로컬 모드 로그아웃 → 온보딩에서 종료 → 재실행 | 이전 계정 복원 없이 로그인/계정 없이 시작 선택 유지 |
| 1 | A의 미전송 메모가 있는 상태로 웹에서 A 삭제 → B 추가 | A 기록이 B에 연결되지 않고 유일본이 보존됨 |
| 1 | 오프라인 한줄평 변경 + 웹 수정 → 재연결 | 충돌 편집을 확인 없이 폐기하지 않음 |
| 1 | 독후감 본문 push를 지연하고 비공개 전환 | 최종 서버 공개 값과 화면이 일치하고 늦은 공개 덮어쓰기 없음 |
| 1 | 탈퇴 요청 지연 중 뒤로 가기 → 서버 성공 | 위젯 생존 여부와 무관하게 로컬 계정/기록 정리 |
| 1 | 가져오기 화면을 닫고 동기화 끄기/켜기/ZIP 진입 | 업로드와 원본 전환/서버 삭제가 동시에 실행되지 않음 |
| 1 | 서버 complete 성공 응답만 차단 후 재시도 | 확정 결과를 복구하고 재첨부 실패·새 편집 유실 없음 |
| 2 | 제목 없는 새 노트가 청크 끝에 오도록 250책/250노트/250메모 | 청크 단위 서버 계약을 만족하며 전체 반영 |
| 2 | 기존 ISBN 책 덮어쓰기 선택 | 안내한 필드가 실제로 바뀌고 메모·태그 보존 |
| 2 | ISBN 없는 CSV complete 응답 유실 후 같은 파일 재선택 | 원래 행을 새 책으로 중복 생성하지 않음 |
| 2 | 신규 노트 작성 화면에서 자동 동기화 발생 | 같은 noteId로 계속 작성 |
| 2 | 로컬 모드에서 이미 존재하는 ISBN 연결 | 안전한 중단 안내, 자동 합치기/삭제 없음 |
| 2 | 직접 등록 저장 중 뒤로 가기·겹친 터치 | 생성 결과가 명확하며 같은 작업은 한 번만 실행 |
| 2 | 토론/답변 제출 지연 중 닫기·리뷰 POST 실패 | 처리 결과가 불명확해지거나 입력이 사라지지 않음 |
| 2 | 검색 실패 후 즉시 통신 복구·재시도 | 수동 재시도가 실제 통신 수행 |
| 2 | ZIP 저장 성공과 취소 반복 | 사용자 파일은 유지하고 작업 임시 파일 정리 |
| 2 | 바코드 홈/잠금/권한 복귀·도움말·프레임 밖 책 | 복귀 후 인식, 잘못된 route pop/엉뚱한 책 등록 없음 |
| 2 | 계정 없는 상태의 바코드 빠른 등록 | 책 메타데이터 확보 또는 명확한 대체 동작 |
| 3 | 공용 카메라 세로/좌우 회전·갤러리 취소·재진입 | 미리보기/촬영 방향/OCR 좌표와 리소스 일치 |
| 3 | 일반 백업 파일 크기에서 분석/ZIP 처리 | UI 정지·메모리 사용을 측정한 뒤 필요한 부분만 조정 |
| 3 | 작은 화면·큰 글자·스크린 리더·키보드 | 주요 버튼·다이얼로그·선택지·목록에 접근 가능 |

## 배제한 대응

일반적이지 않은 다중 프로세스 동시 DB 조작, 악의적으로 조합한 거대 이미지/압축폭탄만을 전제로 한 추가 구조, 모든 화면의 draft 복원 시스템, 모든 요청의 자동 롤백·자동 병합, 상태관리 전면 교체, 취향/스타일 리팩터링은 제안하지 않았습니다. 데이터 유실·비공개 글 노출·탈퇴 정리처럼 중대한 항목은 필요한 경우 범위가 넓은 복구 설계도 포함했습니다.
