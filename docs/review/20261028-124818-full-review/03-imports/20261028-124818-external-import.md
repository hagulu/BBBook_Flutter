# 리뷰 결과

## 요약
선택·충돌 확인과 부모 우선 동기화는 구현돼 있지만, 서버 모드의 덮어쓰기 동작과 화면 밖 작업의 배타 제어가 맞지 않습니다. P1 1건, P2 1건입니다.

## 확인 범위
북적북적 CSV·북모리 파일 선택/공유, 파일 분석, 기본 선택, 같은 ISBN 충돌, 덮어쓰기 확인, 서버/로컬 분기, 청크 전송, 복구 책 메모 정리, 완료 후 재조회, 화면 닫기를 확인했습니다.

## 문제점

### [IMP-01][P2] 서버 모드에서 확인한 ‘기존 기록 덮어쓰기’가 실제로 적용되지 않음

- UI 약속: [lib/features/external_record_import/screens/external_import_screen.dart:129](/Users/hagulu/develop/service/BBBook/project/app/bbbook/lib/features/external_record_import/screens/external_import_screen.dart:129)은 같은 ISBN을 선택하면 책 정보·독서 상태·진행 페이지·별점·한줄평이 가져온 값으로 바뀐다고 안내합니다.
- 근거: [lib/features/external_record_import/services/external_import_snapshot_builder.dart:46](/Users/hagulu/develop/service/BBBook/project/app/bbbook/lib/features/external_record_import/services/external_import_snapshot_builder.dart:46)은 덮어쓰기 때 새 clientRequestId를 만들지만 기존 serverId를 계속 전송합니다. [../../api-doc/api-me-records-import-importId-items-post.md:136](/Users/hagulu/develop/service/BBBook/project/app/bbbook/../../api-doc/api-me-records-import-importId-items-post.md:136)은 clientRequestId·serverId·ISBN 중 어느 기준으로 찾든 **활성 책은 어떤 필드도 수정하지 않고 재사용**한다고 명시합니다. 이번 흐름에는 완료 후 기존 책을 일반 PATCH로 수정하는 단계가 없습니다.
- 영향: 예를 들어 서버의 ‘읽는 중/20쪽’을 CSV의 ‘완독/300쪽’으로 덮어쓰겠다고 확인해도 서버 값은 그대로이며, 가져오기 성공으로 안내됩니다. 로컬 저장 분기와 결과도 다릅니다. 기존 서버 값을 유지하는 서버의 롤백 보호 자체가 문제라는 뜻은 아닙니다.

### [IMP-02][P1] 계속 실행되는 가져오기와 저장 방식 전환이 동시에 시작될 수 있음

- 조건: 큰 파일 가져오기를 시작한 후 ‘화면을 닫아도 가져오기는 계속’ 안내에 동의해 화면을 닫고, 설정에서 동기화를 끄거나 켭니다.

## 개선 제안

- IMP-01: Import가 기존 활성 행을 보존한다는 계약을 유지하면서, 사용자가 명시적으로 고른 기존 책에 한해서 기존 일반 수정 경로를 사용합니다. 그 수정까지 끝난 항목만 덮어쓰기 성공으로 집계하고 부분 실패를 구별해야 합니다. 안전하게 구현하기 전까지는 적용되지 않는 덮어쓰기를 성공으로 표시하지 않는 것이 우선입니다.
- IMP-02: 이미 있는 실행 락을 전환·ZIP·백그라운드 동기화 진입에서도 확인하도록 상호 배타 조건을 맞춥니다. 진행 중 Import를 강제로 취소하거나 세션 데이터를 지우는 방식보다 새 파괴적 작업의 진입을 막는 것이 작고 안전한 대응입니다.

## 확인된 보호 장치

선택된 동일 ISBN 중복을 막고 저장 직전에 새 충돌을 다시 확인합니다. 서버 모드에서는 기존 책·노트·독후감·태그를 사전 동기화하고, 서버 Import 완료 후 노트는 강제 전체 조회로 맞춥니다. 서버 확정 뒤 목록 갱신만 실패하면 가져오기 실패와 구분합니다. 로컬 분기는 한 DB 트랜잭션으로 복원합니다.

## 기기·성능 확인 항목

- 북적북적 CSV의 파싱, 북모리 DB 압축 해제·JSON 변환은 UI isolate에 남아 있습니다. 완독 CSV는 별도 isolate입니다. 일반적인 실제 백업 파일로 프레임 정지 시간을 확인한 후 필요한 CPU 구간만 옮기는 것이 적절하며, 측정 없이 스트리밍 구조 전면 개편을 요구하지 않습니다.
- Android 공유 coordinator는 `canUseApp`만 보고 화면을 열므로 최초 기록 다운로드가 끝나기 전에도 분석 화면이 올라올 수 있습니다. 최초 다운로드 중 가져오기 실행을 기다리게 하는지 후속 통합 검증이 필요합니다. 이번 리뷰에서는 실제 기기에서 이 경쟁을 재현하지 않았습니다.
