# 리뷰 결과

## 요약
행 단위 오류 분리와 가져오기 전 확인은 구현돼 있습니다. ISBN 없는 행의 재선택·재시도 식별자에 P2 1건이 있습니다.

## 확인 범위
CSV 선택, UTF-8/헤더/빈 행/최대 2,000행, 날짜·별점·페이지·태그 검증, 같은 ISBN 제외, 실행 확인, 결과 건수, 오류 후 파일 재선택을 확인했습니다.

## 문제점

### [CSV-01][P2] 완료 응답을 잃고 같은 CSV를 다시 선택하면 ISBN 없는 책이 중복 생성될 수 있음

- 근거: [lib/features/external_record_import/data/finished_csv_importer.dart:309](/Users/hagulu/develop/service/BBBook/project/app/bbbook/lib/features/external_record_import/data/finished_csv_importer.dart:309)은 분석할 때마다 `sourceBookId: uuid.v4()`를 발급합니다. 스냅샷의 책 멱등 키는 그 sourceBookId를 바탕으로 생성됩니다. [lib/features/external_record_import/screens/finished_csv_import_screen.dart:96](/Users/hagulu/develop/service/BBBook/project/app/bbbook/lib/features/external_record_import/screens/finished_csv_import_screen.dart:96) 이후 오류 처리에서는 선택 파일을 비워 재분석하게 합니다.
- 조건: ISBN 없는 정상 행을 포함한 CSV를 가져오는 중 서버 complete는 성공했지만 응답이 유실됩니다. 앱은 실패로 안내하고, 사용자가 같은 파일을 다시 골라 재시도합니다.
- 영향: 이전 UUID를 재사용하지 못하므로 ISBN으로도 멱등 키로도 기존 책을 찾지 못합니다. 같은 책들이 추가 생성될 수 있습니다. ISBN 있는 행은 저장 직전 충돌 제외가 있어 조건이 다릅니다.

## 개선 제안

동일 입력의 같은 행이 재시도에서 동일한 식별자를 갖도록 합니다. 파일 내용/행 위치 또는 정규화한 행 내용과 동일 행의 순번을 함께 사용하는 등 **같은 제목의 서로 다른 행까지 합치지 않는** 좁은 기준이 필요합니다. ‘제목이 같으면 중복’처럼 사용자 기록을 자동 합치는 대응은 피합니다.

## 확인된 보호 장치

- title 외 컬럼은 선택이고 행별 실패 이유를 별도로 보존합니다. 형식이 잘못된 한 행 때문에 나머지 정상 행을 전부 잃지 않습니다.
- 같은 ISBN은 기본 선택에서 제외하고, 저장 직전에 새 충돌이 생기면 남은 행으로 다시 진행합니다.
- 서버 확정 후 목록 재조회 실패와 Import 실패는 구별합니다.
- 저장 방식 전환과의 배타 문제는 공통 controller를 사용하는 [IMP-02](./20261028-124818-external-import.md)에 해당합니다.

## 후속 확인 시나리오

빈 선택/전부 실패/전부 기존 ISBN/ISBN 없는 여러 행/같은 내용의 두 행/오디오북 진행률/완료 응답 유실 후 파일 재선택을 각각 확인합니다. 응답 유실 검증은 실제 기록이 아닌 격리된 데이터로 해야 합니다.
