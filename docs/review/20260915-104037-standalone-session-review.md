# 리뷰 결과

## 요약
- 계정 없이 사용하는 주요 화면과 공개 조회 경로는 연결됐지만, 로컬 기록의 소유권 전환과 로그아웃 처리에 데이터 가시성·서버 삭제 상태 문제가 남아 있습니다.

## 문제점
- [P1] 로컬 저장 모드의 로그아웃 안내가 실제 동작과 반대입니다. `lib/features/profile/screens/profile_screen.dart:632`는 로컬 DB와 사진을 항상 지운다고 설명하고, 647행의 확인창도 모든 기록과 사진이 삭제된다고 경고합니다. 그러나 `AuthNotifier.logout()`은 로컬 모드에서 `_detachAccountFromRecords()`를 호출해 기록을 보존하고 소유자만 계정 없음으로 바꿉니다(`lib/features/auth/providers/auth_notifier.dart:426-427,449-484`). 사용자는 삭제된다고 믿고 로그아웃을 포기할 수 있고, 실제 로그아웃 뒤 기록이 남는다는 개인정보 기대도 충족하지 못합니다.
- [P1] 계정 없는 기록을 로그인 계정으로 넘기는 상태 변경이 원자적이지 않아 앱 종료나 쓰기 실패 시 노트·독후감이 보이지 않을 수 있습니다. `_adoptLocalRecordsForLogin()`은 기록의 `owner_user_id` 변경, `storage_mode.owner_user_id` 변경, `standalone_session_active` 삭제를 각각 별도 작업으로 수행합니다(`lib/features/auth/providers/auth_notifier.dart:312-317`). 첫 작업 뒤 앱이 종료되면 세션은 여전히 standalone으로 복원되어 `recordOwnerId=-1`을 조회하지만 기록 행은 실제 사용자 id로 바뀌어 있습니다. 반대 방향인 로컬 모드 로그아웃도 같은 순서 문제를 갖고 있으며 예외까지 흡수한 뒤 미인증 상태로 전환합니다(`lib/features/auth/providers/auth_notifier.dart:424-434,453-484`). 현재 테스트는 각 저장 작업의 정상 완료만 확인하고 중간 종료 복구는 검증하지 않습니다.
- [P1] 서버 기록 삭제가 보류된 로컬 계정이 로그아웃하면 그 삭제 의무를 영구적으로 잃습니다. `StorageModeStore.switchToStandalone()`은 `server_delete_pending`을 무조건 false로 덮어쓰고(`lib/features/storage_mode/data/storage_mode_store.dart:81-94`), 로컬 로그아웃은 이 메서드를 호출합니다. 서버 삭제가 실패한 상태에서 로그아웃하면 서버에 남은 기록은 이후 같은 계정으로 다시 로그인해도 재시도되지 않습니다. 다른 계정에서 잘못 삭제하지 않으려는 취지는 맞지만, 보류 상태를 버리는 방식은 사용자가 선택한 서버 기록 삭제를 완료하지 못합니다.
- [P2] 인증 선택 공개 GET은 세션 준비에서 발생한 모든 오류를 무시합니다(`lib/core/network/api_client.dart:152-158`). standalone의 “세션 없음”만 허용하려는 코드지만, 로그아웃·계정 전환 중 오류와 실제 토큰 갱신 오류도 함께 삼킵니다. 특히 로그아웃 시작 후 생성 번호가 이미 갱신된 요청은 남아 있는 이전 토큰을 붙여 전송할 수 있고, 같은 생성 번호로 응답까지 수락되어 `isMine`/`likedByMe` 같은 이전 계정 기준 값이 로그아웃 후 캐시에 남을 수 있습니다.

## 개선 제안
- 로컬 로그아웃 안내 불일치 → 보존 정책이 의도라면 확인창을 “계정 연결만 해제하고 기록은 이 기기에 유지되며, 로그인 없이 사용하기로 다시 볼 수 있다”는 내용으로 바꿉니다. 삭제가 정책이라면 notifier를 기존 삭제 동작으로 되돌려 안내와 맞춥니다.
- 소유권 전환 중간 실패 → 같은 SQLite DB의 `book_note`, `book_reflection`, `storage_mode`, `sync_meta` 변경을 하나의 트랜잭션으로 묶고 커밋 뒤 메모리 캐시를 갱신합니다. 하나의 트랜잭션으로 묶기 어렵다면 전환 단계와 목표 소유자를 내구성 있게 기록하고 `_bootstrap()`에서 완료 또는 롤백합니다. 앱 종료 지점을 각 단계 사이에 둔 복구 테스트도 추가합니다.
- 서버 삭제 보류 유실 → 보류 상태와 원래 계정 id를 별도로 보존하고, 같은 계정이 다시 인증됐을 때만 삭제를 재시도합니다. 다른 계정 로그인에서는 해당 상태를 실행하지 않되 폐기하지 않습니다.
- 공개 GET의 예외 전부 무시 → 계정 없음 상태를 명시적인 결과나 전용 예외로 구분해 그 경우에만 익명 요청을 허용합니다. 세션 변경·갱신 실패는 기존처럼 요청을 중단하고, 로그아웃 시작 시점 이후 이전 토큰이 새 공개 요청에 붙지 않도록 검사합니다.
