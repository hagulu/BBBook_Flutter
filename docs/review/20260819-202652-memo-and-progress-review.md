# 리뷰 결과

## 요약
- 메모 조각 정렬·액션 흐름은 대체로 안정적이지만, 진행 쪽수의 빠른 연속 조작 정합성과 두 UI의 접근성 렌더링, 복사 원문 보존에 개선이 필요하다.

## 문제점
- [문제][높음][상태/데이터] `lib/features/book_record/screens/widgets/progress_card.dart:102`~`:126`은 `_apply`에서 화면의 `_committedPage`를 먼저 바꾼 뒤, `_save`가 새 값과 아직 갱신되지 않은 `widget.book.currentPage`를 비교해 저장을 생략한다. 예를 들어 서버·로컬 값이 10인 상태에서 `+`를 눌러 11 저장을 시작하고 곧바로 `-`를 눌러 10으로 돌아오면, 두 번째 10은 기존 `widget` 값과 같아 저장 큐에 들어가지 않는다. 먼저 시작한 11 저장만 완료되어 사용자가 마지막으로 선택한 10과 실제 데이터가 어긋날 수 있다.
- [문제][중간][접근성/렌더링] `lib/features/book_memo/screens/book_memo_detail_screen.dart:542`~`:588`은 타입, 강조 아이콘, 페이지 범위, 상대 시간을 모두 하나의 `Row`에 두면서 텍스트 영역에 `Flexible`이나 줄바꿈 대안을 제공하지 않는다. 좁은 화면에서 시스템 글자 크기를 키우거나 페이지 범위가 길어지면 고정 간격과 두 메타 텍스트가 가용 폭을 초과해 `RenderFlex overflow`가 발생할 수 있다.
- [문제][중간][접근성/렌더링] `lib/features/book_record/screens/widgets/progress_card.dart:256`~`:296`은 증감 버튼 5개를 고정 가로 패딩 18px의 `Row`에 배치한다. 큰 글자 설정이나 폭이 좁은 기기에서는 줄바꿈·스크롤·폭 조절 수단이 없어 오버플로가 발생할 수 있고, 각 `InkWell`의 세로 패딩 10px과 15px 텍스트만으로 구성된 실제 터치 높이도 권장 최소 48px에 미치지 못한다.
- [문제][낮음][데이터 보존] `lib/features/book_memo/screens/book_memo_detail_screen.dart:354`~`:361`은 강조 마크업을 제거한 뒤 바로 `trim()`한 문자열을 클립보드에 쓴다. 화면의 `_MemoRichText`는 앞뒤 공백과 줄바꿈을 그대로 표시하므로, 들여쓰기나 문단 앞뒤 줄바꿈이 의미 있는 발췌를 복사하면 표시된 원문과 다른 텍스트가 저장된다.

## 개선 제안
- 진행 쪽수 저장 생략 기준 → 아직 갱신되지 않은 `widget.book.currentPage`와 비교해 요청을 건너뛰지 말고, 마지막으로 저장 큐에 넣은 값을 별도로 추적하거나 모든 사용자 적용 값을 순서대로 `updateRecord` 체인에 전달해 최종 조작이 반드시 반영되게 한다.
- 메타 헤더 가로 배치 → 타입·페이지 묶음과 시간을 반응형으로 나누거나 `Wrap`/`Flexible`을 적용해 큰 텍스트 배율과 긴 페이지 범위에서도 줄바꿈 또는 축약이 가능하게 한다.
- 증감 툴바 고정 `Row` → 가용 폭에 따라 버튼 폭을 조절하거나 `Wrap`/가로 스크롤을 제공하고, 각 액션의 최소 터치 높이를 48px 이상 보장한다.
- 복사 전 `trim()`으로 원문을 변경 → `plainText.trim().isEmpty`는 복사 가능 여부 판단에만 사용하고, 실제 `ClipboardData`에는 마크업만 제거한 `plainText` 원문을 전달한다.
