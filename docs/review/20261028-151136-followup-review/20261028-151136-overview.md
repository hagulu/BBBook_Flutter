## 개선 제안

1. FUP-01: 최신 서버 값을 확인하지 못한 실패는 dirty를 보존하고 다음 동기화로 넘깁니다. HTTP 응답 유무를 서버 값이 더 최신이라는 근거로 쓰면 안 됩니다.
2. FUP-02: 완료 결과가 불명확한 작업을 일반 실패와 구분하고, 동일 작업의 확정 여부·매핑을 복구한 뒤 다음 Import를 허용합니다. 데이터 무결성 문제이므로 이 항목은 필요한 복구 상태까지 검토 범위를 넓힐 가치가 있습니다.
3. FUP-03·04: 해당 시트의 실제 드래그 닫기 경로와 전송 중 입력만 제한하는 작은 대응이 적절합니다.

일반 오류를 성공으로 간주하거나, 무제한 재시도하거나, 서버 데이터를 자동 삭제하거나, 모든 화면의 내비게이션·상태관리를 바꾸는 대응은 제안하지 않습니다. 기존 개선이 효과 있는 부분은 유지하고 확인된 실패 경로에 집중합니다.
