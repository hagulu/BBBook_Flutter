# 리뷰 결과

## 요약

- 직전 리뷰에서 지적한 진행률 슬라이더 문제는 해소됐고 정적 분석도 통과했지만, 새 선택 UI의 접근성과 아이콘 정책 충돌이 남아 있다.
- 검증: `flutter analyze`는 `No issues found`로 통과했다. 프로젝트 지침에 따라 앱 실행과 테스트는 수행하지 않았다.

## 문제점

- [문제][중간][접근성/렌더링] `lib/features/book_record/screens/widgets/meta_dialogs.dart:21`~`:34`와 `:79`~`:98`은 상태 카드를 `childAspectRatio: 1`인 정사각형으로 고정한다. 좁은 화면이나 큰 텍스트 배율에서는 `읽고 싶음` 같은 라벨이 여러 줄로 바뀌지만 카드 높이는 늘지 않아 아이콘·간격·텍스트를 합친 `Column`이 세로로 overflow할 수 있다.
- [문제][중간][접근성] `lib/app/main_shell.dart:78`~`:99`는 세 탭 모두 일반 아이콘을 `icon`과 `selectedIcon`에 동일하게 전달한다. `_NavItem`도 선택 상태를 시맨틱스로 노출하지 않아 활성 탭이 색상으로만 구분되고, 스크린 리더는 어느 탭이 선택됐는지 알 수 없다.
- [문제][중간][접근성] `lib/features/book_record/screens/widgets/meta_summary_card.dart:45`~`:57`과 `:103`~`:117`의 시작일·완독일 버튼은 각각 날짜 문자열만 읽히므로 둘 다 미설정이면 스크린 리더에 동일한 `년.월.일` 버튼으로 노출된다. 세로 터치 영역도 텍스트 높이와 8dp 패딩 정도에 그쳐 모바일 조작 영역으로 작다.
- [문제][중간][프로젝트 규칙] `AGENTS.md:28`~`:29`는 Material Icons를 기본으로 사용하도록 규정하지만, 이번 변경은 `pubspec.yaml:45`에 `phosphor_icons`를 추가하고 기존 Material 아이콘을 전면 교체했다. 동시에 `CLAUDE.md:27`~`:29`는 Phosphor 사용을 요구하도록 바뀌어 두 최상위 작업 지침도 서로 충돌한다. 현재 기준으로는 어떤 아이콘 체계를 후속 구현이 따라야 하는지 일관되게 결정할 수 없다.

## 개선 제안

- 상태 카드가 정사각형 높이에 고정됨 → `MediaQuery.textScaler`와 가용 폭을 반영해 행 높이를 늘리거나, 콘텐츠 높이에 맞게 확장되는 `Wrap`/반응형 레이아웃으로 바꿔 큰 텍스트에서도 최소 터치 영역과 라벨 전체 표시를 보장한다.
- 하단 탭의 활성 상태가 색상에만 의존함 → 선택 시 채워진 아이콘을 사용하고 `_NavItem`에 `Semantics(selected: selected, ...)`를 적용해 시각·스크린 리더 양쪽에 상태를 전달한다.
- 두 날짜 버튼의 의미와 터치 영역이 불명확함 → 각각 `시작일`/`완독일`을 포함한 시맨틱 라벨을 제공하고 최소 48dp 높이의 조작 영역을 확보한다.
- 아이콘 지침과 구현이 충돌함 → Material 또는 Phosphor 중 하나를 프로젝트 기준으로 확정해 `AGENTS.md`와 `CLAUDE.md`를 동일하게 맞춘 뒤, 그 기준에 따라 의존성과 아이콘 변경 범위를 정리한다.
