# 리뷰 결과

## 요약

- 카메라를 빠르게 다시 열 때 새 화면의 미리보기가 해제될 수 있는 P2 문제 1건을 확인했다.
- 범위: 현재 미커밋 변경 파일 4개(공용 카메라, 노트 DAO, 사진 동기화 테스트, 릴리즈 APK 스크립트)와 관련 호출부·설치된 카메라 플러그인·Import API 문서.
- 검증: `flutter analyze`는 `No issues found!`로 통과했고 `git diff --check`도 통과했다. 앱 실행과 테스트는 수행하지 않았다.

## 문제점

- [P2][화면 간 카메라 소유권이 보장되지 않아 재진입 시 새 미리보기가 해제됨] `lib/shared/image/screens/shared_camera_screen.dart:135` — `_cameraSessionChain`은 등록된 작업의 실행 순서만 보장하며, 이전 화면의 컨트롤러가 살아 있는 동안 새 화면이 초기화되는 것은 막지 못한다. `showSharedCameraScreen()`의 `Navigator.push()` 결과는 pop 애니메이션 종료와 이전 화면의 `dispose()`보다 먼저 완료되므로, 닫기 직후 다시 촬영 화면을 열면 큐가 `이전 초기화 → 새 초기화 → 이전 해제` 순서가 될 수 있다. 설치된 `camera_android_camerax 0.7.4+5`의 `dispose(cameraId)`는 전달된 ID의 리소스를 찾지 않고 플러그인 전역 `preview`에 `releaseSurfaceProvider()`를 호출한 뒤 `unbindAll()`을 수행한다. 따라서 큐에서 작업이 겹치지 않아도 이전 컨트롤러의 늦은 해제가 새 카메라를 해제하며, 새 화면은 `_controller`가 설정된 상태로 남아 미리보기 중단·촬영 실패가 발생할 수 있다. 현재 직렬화 변경으로도 이 화면 재진입 경합은 남는다.

## 개선 제안

- 이전 화면의 해제가 새 카메라를 해제하는 경합 → 큐와 함께 화면 간 활성 컨트롤러 소유권을 관리한다. 새 컨트롤러를 생성하기 전에 이전 소유자의 컨트롤러 해제를 완료하고 이전 상태를 무효화하며, 이전 화면의 뒤늦은 `dispose()`가 새 세션을 해제하지 않도록 한다.
