# 리뷰 결과

## 요약
- 공통 `AppSnackBar` 도입과 호출부 교체는 정적 분석을 통과했지만, 오류 메시지의 색상 대비와 전역적인 메시지 큐 초기화 동작은 보완이 필요하다.

## 문제점
- [접근성] `lib/shared/widgets/app_snackbar.dart:91`에서 오류 배경색 `AppColors.error`를 88% 불투명도로 합성하고 그 위에 14px 흰색 텍스트를 표시한다. 밝은 화면 위에서 합성된 색상은 약 `#E45353`이고 흰색과의 대비가 약 3.71:1이라 일반 크기 텍스트의 권장 대비 4.5:1에 미달한다. 오류 안내가 주로 밝은 배경의 화면에 표시되므로 저시력 사용자가 내용을 읽기 어려울 수 있다.
- [사용자 안내] `lib/shared/widgets/app_snackbar.dart:22`의 `clearSnackBars()`가 모든 `success`/`info`/`error` 호출에 무조건 적용된다. 기존 호출부 대부분은 `showSnackBar()`만 사용해 여러 안내가 발생하면 순서대로 노출했지만, 공통 위젯으로 교체된 뒤에는 뒤이어 발생한 메시지가 현재 메시지와 대기 중인 메시지를 모두 제거한다. 커뮤니티 리뷰처럼 여러 비동기 동작이 가능한 화면에서는 먼저 발생한 실패 안내가 성공 또는 준비 중 안내에 의해 읽기도 전에 사라질 수 있다.

## 개선 제안
- 오류 배경의 낮은 색상 대비 → 반투명 합성 후에도 흰색과 4.5:1 이상 대비되는 더 어두운 오류 배경 토큰을 사용하거나, 배경색과 함께 대비가 보장되는 전경색 토큰을 정의한다. 실제 합성 결과를 기준으로 밝은 화면과 어두운 화면 모두에서 대비를 확인한다.
- 모든 메시지에서 기존 큐 제거 → 기본 `show()`는 기존 `ScaffoldMessenger`의 큐 동작을 유지하고, 연속 스캔처럼 최신 메시지만 남겨야 하는 호출부에만 `replaceCurrent` 같은 옵션을 명시해 큐를 비우도록 분리한다.
