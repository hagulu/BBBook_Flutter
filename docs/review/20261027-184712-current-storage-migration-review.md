## 문제점

- [P1] **새 이미지 확보 전에 삭제 기준을 갱신하여, 정리 재시도에서 이미지를 잃을 수 있다.**

  위치: `lib/features/storage_mode/services/local_storage_migration_service.dart:284–290`, `lib/features/storage_mode/providers/storage_mode_providers.dart:101–108`.

  다른 기기에서 사진 메모를 추가해 첫 DELETE가 409로 거절되면, `_cleanUpServerRecords()`는 최신 기록을 반영한 직후 새 `exportedAt`을 영속 저장한다. 이미지 다운로드와 누락 검사는 그 뒤에 실행된다. 이때 다운로드가 실패하거나 사용자가 누락 이미지 상태로 진행하는 것을 거절하거나 앱이 종료되면, 로컬 모드와 갱신된 삭제 기준만 남는다.

  이후 설정의 ‘서버 기록 정리 → 다시 시도’는 `retryServerCleanup()`에서 이미지 다운로드·누락 검사 없이 저장된 시각으로 DELETE를 호출한다. 새 시각 이후 서버 변경이 없다면 서버는 삭제를 허용하므로, 아직 이 기기에 없는 사진을 확보하지 않은 채 서버 기록을 정리하게 된다. `ServerStorageMigrationRepositorySteps.ensureNoPendingServerCleanup()`의 서버 모드 복귀 전 정리도 같은 저장값을 사용한다. 사용자가 이미지 손실을 승인하지 않았어도 이 경로가 실행될 수 있다.

## 개선 제안

- 이미지 확보와 삭제 허용 상태가 분리되어 저장되는 문제 → 갱신된 `exportedAt`은 이미지 확보·검증이 끝났거나 사용자가 누락을 명시적으로 승인한 뒤 확정한다. 앱 종료 뒤 재시도와 서버 모드 복귀 전 정리에서도 이미지 확보 여부를 확인하고, 미확보 이미지가 있으면 다운로드 또는 손실 동의 과정을 거친 뒤 삭제한다. 이때 로컬 모드에서 작성·삭제한 기록을 서버 스냅샷으로 덮어쓰지 않도록 이미지 확보 단계만 재개해야 한다.
- 검증할 경계 조건 → 409 후 새 사진 다운로드 실패, 누락 상태 진행 거절, 다운로드 도중 앱 종료 각각에서 정리를 재시도해도 이미지 확보 또는 사용자 동의 전에는 DELETE가 실행되지 않는지 확인한다.
