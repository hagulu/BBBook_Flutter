# 리뷰 결과

## 요약

- 미커밋 Flutter 변경사항인 `lib/app/main_shell.dart`를 검토한 결과, 하단 콘텐츠 가림과 큰 글자 설정의 가로 오버플로 문제 2건을 확인했다. `flutter analyze`는 통과했다.
- 관련 책장·프로필 화면을 함께 확인했으며, 앱 실행과 테스트는 수행하지 않았다. 아래 레이아웃 문제는 코드의 제약 조건을 기준으로 판단했다. 기존 문서·참고 이미지의 추가 및 삭제는 기능 리뷰 범위에서 제외했다.

## 문제점

- [P2] 프로필의 마지막 로그아웃 버튼이 하단 메뉴에 가려진다 — `lib/app/main_shell.dart:149–159`. 기존 `bottomNavigationBar`가 차지하던 공간이 사라지고 `IndexedStack` 위에 메뉴가 겹치지만, `profile_screen.dart:174–175`의 스크롤 하단 여백은 32로 유지된다. 콘텐츠가 화면보다 길어 끝까지 스크롤한 경우 중앙의 로그아웃 버튼은 화면 바닥에서 약 32–80 높이에 위치하고, 메뉴는 최소 16–76 구간을 차지하므로 버튼 글자와 터치 영역이 겹친다. 하단 안전 영역이 있으면 가림 범위가 더 커진다. 스크롤을 끝까지 내려도 버튼을 메뉴 위로 올릴 수 없다.

- [P2] 좁은 화면에서 글자를 확대하면 하단 메뉴가 가로로 넘친다 — `lib/app/main_shell.dart:160–164`, `lib/app/main_shell.dart:281–303`. 바깥 Row와 pill 내부 Row 모두 자식의 고유 너비를 사용하고 축소 가능한 자식이 없다. 두 탭의 수평 패딩·아이콘·간격, pill 패딩, 추가 버튼과 간격만 약 184이며 여기에 네 글자의 확대된 너비가 더해진다. 예를 들어 화면 너비 320에서 좌우 여백을 뺀 가용 너비는 288인데, 글자 배율 2.5에서는 텍스트를 포함한 메뉴 너비가 약 314가 되어 RenderFlex 오버플로가 발생한다. 고정 높이도 있어 더 큰 글자는 세로 공간이 부족해진다.

## 개선 제안

- 하단 콘텐츠 가림 → 메뉴 높이와 실제 하단 안전 여백을 반영한 스크롤 끝 여백을 탭 콘텐츠에 제공한다. 책장은 기존 88 여백을 사용하고 있으므로 프로필과 함께 안전 영역이 큰 기기에서도 마지막 항목을 완전히 드러낼 수 있는지 확인한다.
- 큰 글자 설정의 메뉴 오버플로 → 가용 너비와 텍스트 배율에 따라 탭 배치를 전환하거나 탭 너비·높이를 유연하게 구성한다. 320 너비와 큰 글자 설정에서도 레이블과 책 추가 버튼이 모두 화면 안에 들어오도록 한다.
