# 리뷰 결과

## 요약

- 완독 검색의 메모·독후감 포함 기능에서 검색 결과의 최신성·정확성에 영향을 주는 P2 문제 2건을 확인했다.
- 범위: 현재 미커밋 변경 파일 6개(완독 검색 DAO·Repository·필터 모델·Provider·화면, 릴리즈 APK 스크립트)와 관련 기록 저장·동기화·화면 복귀 경로.
- 검증: 코드 흐름을 대조했으며 `flutter analyze`는 `No issues found!`로 통과했다. `git diff --check`도 통과했다. 앱 실행과 테스트는 수행하지 않았다.

## 문제점

- [P2][기록 변경 후 완독 검색 결과가 갱신되지 않음] `lib/features/bookshelf/providers/bookshelf_providers.dart:218` — `finishedBooksProvider`는 이제 메모·독후감 내용에 의존하지만, 재조회 신호는 여전히 책장 버전·필터·소유자 등에 한정된다. 독후감 저장·삭제는 `bookReflectionSyncVersionProvider`를 올리고, 기록 증분 동기화도 각각 `bookNoteSyncVersionProvider`·`bookReflectionSyncVersionProvider`만 올린다. 이 신호를 구독하지 않으며, 완독 카드에서 상세로 이동했다 돌아올 때도 검색 결과를 무효화하지 않는다. 따라서 ‘메모·독후감 포함’ 검색에서 찾은 책의 유일한 일치 메모를 수정하거나 일치 독후감을 삭제한 뒤 돌아오면 해당 책이 결과에 계속 남는다. 반대로 기록 동기화로 새로 일치한 책은 결과에 추가되지 않는다. 특히 로컬 저장 모드에서는 서버 동기화에 따른 우연한 갱신도 없어, 검색어·옵션 변경 등으로 재조회하기 전까지 이전 결과가 유지된다. 로컬 메모 편집은 상세 상태와 해당 책의 노트 목록만 갱신하므로, 기록 동기화 버전 구독만 추가해서는 이 경로까지 해결되지 않는다.

- [P2][강조 마크업 경계를 지나는 검색어가 메모와 일치하지 않음] `lib/features/bookshelf/data/bookshelf_dao.dart:176` — `m.content LIKE ?`는 사용자에게 보이는 평문 대신 `::hl[[...]]` 강조 마크업이 포함된 저장 문자열을 비교한다. 메모 편집기는 `MemoHighlightController.toRaw()`로 마크업을 직렬화하고 DAO는 이를 그대로 `content`에 저장한다. 예를 들어 화면에 ‘삶의 의미’로 보이는 메모에서 ‘의미’만 강조하면 저장값은 `삶의 ::hl[[의미]]`이므로, 검색어 `삶의 의미`는 일치하지 않는다. 책 정보·다른 기록에 같은 문구가 없으면 해당 책이 결과에서 빠진다. 내용이 같은 메모도 강조 적용 여부에 따라 검색 결과가 달라진다.

## 개선 제안

- 기록 변경 후 검색 결과 유지 → 검색어가 있고 `includeRecords`가 켜진 경우 기록 변경 신호도 구독한다. 노트·메모의 로컬 생성·수정·삭제 경로에서도 검색을 갱신할 신호를 발생시키거나 검색 Provider를 무효화한다. 독후감 로컬 저장·삭제와 양쪽 기록 동기화 신호도 연결한다.
- 강조된 메모의 검색 누락 → `stripMemoHighlightMarkup`과 같은 규칙으로 강조 마크업을 제거한 평문을 검색 대상으로 사용한다. 검색용 평문을 별도로 저장한다면 로컬 작성·수정, 동기화, 가져오기 경로에서 함께 갱신한다.
