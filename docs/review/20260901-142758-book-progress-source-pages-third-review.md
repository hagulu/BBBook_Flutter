# 리뷰 결과

## 요약
- 출처 변경 시 진행률 초기화 정책과 요청 순서는 정리됐지만, 새 서버 우선 경로가 기존 dirty push와 경합하고 2단계 저장의 중간 실패 및 순수 출처 변경에서 로컬·화면·서버 상태가 갈라질 수 있다.

## 개선 제안
- 기존 dirty push와의 경합 → 출처·쪽수 조정 작업도 `BookshelfRepository`의 책별 쓰기 큐에 합류시키고, 실행 시점에 dirty 행을 확인한다. 기존 dirty push를 성공적으로 확정한 뒤 최신 서버 기준으로 조정 PATCH를 보내거나, pending 필드까지 하나의 record PATCH에 합쳐 `confirmPush`와 같은 세대·스냅샷 보호로 확정한다. 컨트롤러에서도 `_editChain`이 끝나기 전에 서버 우선 변이가 시작되지 않도록 같은 직렬화 경계를 사용한다.
- 2단계 저장의 중간 실패 → 첫 record PATCH가 성공한 뒤에는 예외가 발생해도 컨트롤러를 작업 전 상태로 되돌리지 말고 최소한 `afterRecord`와 실제 DB 상태를 화면에 유지한다. 미완료 book-info 단계를 재시도할 수 있도록 작업 상태를 보존하거나 보상 동작을 명시하고, 성공한 첫 단계까지 숨기는 일반 `_mutate()` 롤백 경로와 분리한다.
- 순수 출처 변경의 오래된 상태 → display 변경 여부와 무관하게 출처 저장을 리포지토리의 단일 진입점으로 보내 실행 시점의 최신 `BookItem`에서 초기화 여부를 계산한다. 다이얼로그 이후 최신 진행 기록 때문에 새로 초기화가 필요해졌다면 저장 전에 확인을 다시 받아, 경고와 실제 적용 결과가 일치하도록 한다.
