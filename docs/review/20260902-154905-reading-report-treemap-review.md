# 리뷰 결과

## 요약
- 하단 탭 개편과 독서 리포트 차트 교체는 구조·생명주기 처리가 대체로 적절하지만(`flutter analyze` 0건, `app-release.apk` 빌드 성공), 새 release beta 빌드가 cleartext 차단으로 API 호출이 전부 실패하는 문제 1건과 재독 횟수 오집계·레이아웃·정보 손실 문제 4건이 있습니다.

## 문제점
- [문제] `.vscode/launch.json`의 `bbbook (release beta)`와 `scripts/build_release_apk.sh:7`이 `API_BASE_URL=http://192.168.0.51:8081`(평문 HTTP)로 **release** 빌드를 만들지만, cleartext 허용은 `android/app/src/debug/AndroidManifest.xml:9`에만 있고 `android/app/src/main/AndroidManifest.xml:9`의 `<application>`에는 없습니다. 실제 병합 결과(`build/app/intermediates/merged_manifest/release/processReleaseMainManifest/AndroidManifest.xml`)도 `targetSdkVersion="36"`에 `usesCleartextTraffic`·`networkSecurityConfig`가 모두 없습니다. Android 9(API 28) 이상은 평문 HTTP가 기본 차단이므로 이 APK는 설치·실행은 되어도 로그인부터 모든 요청이 `CLEARTEXT communication to 192.168.0.51 not permitted`로 실패합니다.
- [문제] `lib/core/config/api_config.dart:19`의 `assertConfiguredForRelease()`는 "release 빌드에 로컬 개발용 기본값이 그대로 들어가는 것"을 막으려는 가드인데, `_devDefault`가 `:8080`이고 새 스크립트가 `:8081`이라 포트만 다를 뿐 여전히 개발 PC의 LAN 주소인 채로 가드를 통과합니다. 테스터에게 배포되는 APK가 개발 PC를 가리키게 되고, 개인 LAN IP가 리포지토리에 하드코딩된 채 남습니다.
- [문제] `lib/features/profile/services/reading_stats_calculator.dart:93`이 재독 횟수를 `item.rereadCount > 1 ? item.rereadCount - 1 : 0`으로 바꾸면서 실제 저장값보다 한 권당 1회씩 적게 집계합니다. 앱의 쓰기 경로상 `rereadCount`는 0-based 재독 횟수입니다 — 책 생성 시 `0`(`lib/features/bookshelf/data/bookshelf_repository.dart:405`), 첫 완독은 `finishedAt == null` 분기라 `RecordPatch`에 `rereadCount`를 아예 보내지 않아 `0` 유지(`lib/features/book_record/screens/book_record_screen.dart:444`), 두 번째 완독에서 `showRereadDialog(initialCount: book.rereadCount + 1)`로 `1`이 저장됩니다(`book_record_screen.dart:407`, 팝업 제목도 "재독 횟수" — `reread_dialog.dart:79`). 즉 **두 번 읽은 책은 `rereadCount == 1`**인데 새 식은 `1 > 1`이 false라 0을 더해, 두 번 읽은 책이 통계에서 완전히 사라지고 세 번 읽은 책은 1로 계산됩니다. 이 화면은 서버 통계 API가 아니라 로컬 데이터로 계산하므로 로컬 쓰기 경로가 판단 기준이며, 이 변경은 직전 커밋 `4024ae3`이 주석으로 근거까지 남겨 확정했던 결론을 새 근거 없이 되돌린 것입니다.
- [문제] 위와 관련해 서버 문서 표기에 실제 모순이 있어 확인이 필요합니다. `../../api-doc/api-me-books-userBookId-patch.md:28`은 `재독 횟수 (0 이상)`이라 하고, `../../api-doc/api-me-reading-stats-summary-get.md:32`는 `rereadCount - 1 기준, 처음 읽은 책은 0`이라 해 서버 원본 컬럼이 1-based임을 시사합니다. `BookItem.fromJson`(`lib/features/bookshelf/models/book_item.dart:348`)은 서버 값을 그대로 받으므로 **서버 동기화된 책의 base가 무엇인지**는 백엔드 확인 사항입니다(CLAUDE.md 규칙). 참고로 `book_record_screen.dart:360`의 `rereadCount >= 2 → '완독 · N회'` 표시는 1-based를 가정한 듯 보이지만, 0-based 기준으로 보면 그 표시 자체가 1회 어긋난 별개의 문구 문제이며(3회 읽은 책이 "2회"로 표시) 위 계산 회귀와는 무관합니다.
- [문제] `lib/app/main_shell.dart`가 `_AddNavItem`(하단 탭 바 안에 있어 아무것도 가리지 않았음)을 `floatingActionButton`으로 바꾸면서, 책장 탭 목록의 마지막 행이 FAB에 가립니다. FAB는 기본 크기 56 + 여백 16으로 본문 우하단 약 72dp를 차지하는데, 네 탭 뷰의 스크롤 하단 패딩은 모두 24입니다(`simple_grid_tab_view.dart:42`, `reading_tab_view.dart:31`, `finished_tab_view.dart:413`). 끝까지 스크롤하면 마지막 책 카드/행의 우측이 FAB에 덮여 탭할 수 없습니다.
- [문제] `lib/features/profile/screens/profile_screen.dart:383`의 "내 글 모아보기" 2×2 그리드가 세로 여유가 사실상 0이라 텍스트 배율을 조금만 올려도 `RenderFlex overflow`가 납니다. `childAspectRatio: 2` + `crossAxisSpacing: 10` + 화면 패딩 16 + 카드 패딩 `all(14)` 기준으로 360dp 화면의 셀 내부 가용 높이는 51.5dp인데, 내용은 아이콘 박스 36dp + 14px 라벨 1줄입니다. 계산해 보면 배율 1.0에서 50.0(여유 1.5), 배율 1.3에서 54.0(**2.5 초과**), 320dp 화면은 가용 41.5로 기본 배율에서도 **8.5 초과**입니다. 배율 1.0 수치는 테스트 폰트(줄높이 = fontSize) 기준이라 낙관적이며, 실제 한글 폴백 글꼴 줄높이(약 1.35~1.4)로는 360dp/배율 1.0도 여유가 없고 배율 1.15 부근부터 깨집니다.
- [문제] `lib/features/profile/screens/widgets/reading_stats_category_chart.dart:172`, `:186`의 `SizedBox(width: 48)` 안 `'$percent%'`(13px, w800)와 `'${category.count}권'`(12px, w600)에 `maxLines`·`overflow` 지정이 없습니다. 배율 1.4 이상에서 `100%`나 세 자리 권수가 48dp를 넘깁니다. 위 그리드와 달리 이쪽은 기본 `TextOverflow.clip`으로 **경고 배너 없이 조용히 잘려서** 디버그 중에도 눈에 띄지 않습니다.
- [문제] 도넛 차트와 함께 있던 상시 범례(`_CategoryLegend` — 이름 + % + 권수)가 삭제되고 이름·수치가 "자세히" 토글(`_showDetails` 기본 `false`) 뒤로 들어가면서, 기본 화면에서 장르를 식별할 방법이 사라졌습니다. 트리맵 타일 라벨은 `reading_stats_treemap.dart:248`에서 `contentRect.width < 34 || contentRect.height < 20`이면 아예 그리지 않고, 카테고리 마스터 캐시에 색이 없으면 전부 같은 회색으로 칠해집니다(`reading_stats_summary.dart:31`). 카테고리가 많은 연도에서는 이름 없는 작은 타일과 동일한 회색 타일이 늘어서 토글을 발견하기 전까지 무엇인지 알 수 없습니다. 회색 폴백 자체는 기존 동작이지만, 그것을 보완하던 범례가 없어진 것은 이번 변경으로 생긴 정보 손실입니다.

## 개선 제안
- cleartext 차단 → 베타 백엔드를 `https`로 올리고 `scripts/build_release_apk.sh`·`launch.json`의 URL을 교체하는 것이 정공법입니다. 임시로는 `android/app/src/main/res/xml/network_security_config.xml`에 해당 호스트만 `cleartextTrafficPermitted="true"`인 `domain-config`를 두고 매니페스트에 `android:networkSecurityConfig`로 연결합니다(전체 허용인 `usesCleartextTraffic="true"`는 피합니다).
- 개발 PC 주소 하드코딩 → 스크립트가 `API_BASE_URL="${1:-$API_BASE_URL}"`처럼 인자/환경변수를 받게 해 리포지토리에 개인 LAN IP를 고정하지 않고, `assertConfiguredForRelease()`도 값 비교 대신 "https 스킴 여부"나 "사설 IP 대역 여부"로 검사하면 가드 의도가 실제로 지켜집니다.
- 재독 횟수 → 서버 동기화 값의 base를 백엔드에 확인한 뒤 결정합니다. 로컬 기준(0-based)이 맞으면 이전 식(`sum + item.rereadCount`)으로 되돌리고, 서버가 1-based로 내려주는 것이 확인되면 보정 지점을 계산기가 아니라 `BookItem.fromJson`이라는 경계 한 곳으로 옮겨 로컬·서버 값의 의미를 통일합니다. 어느 쪽이든 판단 근거를 주석으로 남겨 두면 이번처럼 재논의되는 것을 막을 수 있습니다.
- FAB 가림 → 책장 탭 스크롤 뷰들의 하단 패딩을 FAB 높이 + 여백(약 80)까지 늘립니다. 네 탭 뷰에 흩어진 `fromLTRB(16, ..., 16, 24)` 값을 공통 상수로 뽑아 한 곳에서 관리하면 이후 FAB 크기 변경에도 안전합니다.
- 텍스트 배율 오버플로 → 두 곳 모두 "고정 치수 + 가변 텍스트" 조합이 원인이라 함께 정리하는 편이 낫습니다. 그리드는 `childAspectRatio` 대신 `SliverGridDelegateWithFixedCrossAxisCount(mainAxisExtent: ...)`로 높이를 직접 주고 `MediaQuery.textScalerOf(context).scale(14)` 기준으로 필요한 높이를 계산합니다. 숫자 상세 행은 `SizedBox(width: 48)`를 `ConstrainedBox(minWidth: 48)`로 바꾸거나, 최소한 두 `Text`에 `maxLines: 1`과 `TextOverflow.ellipsis`를 지정해 잘림이 드러나게 합니다.
- 장르 식별성 → `_showDetails` 기본값을 `true`로 두거나, 트리맵 아래에 접히지 않는 압축 범례(색 점 + 이름) 한 줄을 남기거나, 라벨을 못 그리는 작은 타일이 하나라도 있으면 상세를 자동으로 펼칩니다. 색을 못 찾은 카테고리가 여러 개일 때 전부 같은 회색이 되는 문제는 `categoryId` 기반 폴백 팔레트(고정 색 배열에서 인덱스 선택)로 완화할 수 있습니다.
- 차트 인터랙션 일관성 → 트리맵은 같은 타일을 다시 탭하면 툴팁이 닫히는데(`reading_stats_treemap.dart:44`) 월별 선그래프는 같은 월을 다시 탭해도 닫히지 않습니다(`reading_stats_monthly_chart.dart:46`, 클래스 주석상 의도된 동작). 같은 화면의 두 차트가 다르게 반응하므로 한쪽으로 맞추는 것을 검토할 만합니다.
- ProGuard 확인 → `-dontwarn` 규칙 추가는 적절하고, `build/app/outputs/mapping/release/mapping.txt`가 생성된 것으로 보아 R8이 실제로 동작해 규칙도 반영됩니다. 다만 `getDefaultProguardFile("proguard-android-optimize.txt")`는 비-optimize 버전보다 공격적이라 리플렉션을 쓰는 플러그인(ML Kit OCR, `mobile_scanner`, `pro_image_editor`)에서 런타임에만 드러나는 문제가 생길 수 있습니다. release APK로 바코드 스캔·텍스트 인식·이미지 편집을 한 번 확인하고, 문제가 있으면 `proguard-android.txt`로 낮추는 것을 권합니다.
