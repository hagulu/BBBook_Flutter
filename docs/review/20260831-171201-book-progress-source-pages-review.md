# 리뷰 결과

## 요약
- 종이책/전자책/오디오북별 진행률 계산은 모델에 모였지만, 책 형태와 전자책 쪽수를 서로 다른 PATCH로 저장하면서 경합·부분 저장이 생기고 출처 전환 뒤 쪽수 상태가 모순될 수 있다.

## 문제점

## 개선 제안
- 책 형태 저장 PATCH 경합 → 컨트롤러/리포지토리에 책 형태와 `displayTotalPages`를 함께 저장하는 단일 작업을 두고 두 서버 요청을 같은 직렬화 경로에서 처리한다. 서버 모드에서는 먼저 book-info 응답의 최신 `updatedAt`을 로컬 기준값에 반영한 뒤 record PATCH를 보내거나, record push 완료를 명시적으로 기다린 뒤 book-info PATCH를 보내 결과가 요청 순서에 의존하지 않게 한다. 로컬 모드도 두 필드를 하나의 조정된 작업으로 반영한다.
- 숨은 전자책 override 유지 → 전자책이 아닌 형태로 전환할 때 기존 `displayTotalPages`가 있으면 `PatchField.clear()`를 반환해 명시적으로 제거하고, 전자책→실물책 및 전자책→오디오북→실물책 전환 테스트를 추가한다.
- 출처별 진행률 단위 불일치 → 출처 변경 작업에서 새 출처의 상한을 기준으로 `currentPage`를 함께 검증·조정한다. 단위 변환 기준을 자동으로 정할 수 없다면 저장 전에 사용자에게 새 진행률 입력을 받되, 최소한 오디오북은 0~100이고 나머지는 유효 총쪽수 이하인 상태만 로컬과 서버에 남도록 보장한다.
- 무응답·부분 저장 오류 → 조정된 저장 작업 전체에 공통 로딩과 `ApiException` 처리를 적용해 실패를 `AppSnackBar.error()`로 알린다. `displayTotalPages`가 현재 진행값보다 작은 경우는 요청 전에 검증해 다이얼로그 안에서 안내하고, 서버 요청 중 하나만 성공했을 때의 재시도 정책도 한 작업 안에서 처리한다.
