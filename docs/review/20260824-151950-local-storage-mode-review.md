# 리뷰 결과

## 요약
- 정적 분석은 통과했지만, 로컬 책 삭제 후 하위 기록이 새 책에 붙을 수 있는 데이터 정합성 문제와 로컬 전용 저장 약속이 깨지는 여러 누락 경로가 있습니다.

## 개선 제안
- 로컬 책 삭제 시 하위 기록 잔존 및 ID 재사용 → 삭제 전에 연결된 메모·독후감 이미지 경로를 수집하고, `book_note_memo`/`book_note`/`reflection_image_local`/`book_reflection`/태그/책을 하나의 DB 트랜잭션으로 정리한 뒤 파일을 삭제합니다. 로컬 ID도 삭제 여부와 무관한 영속 시퀀스로 발급하거나, 최소한 하위 행 정리가 완료되기 전에는 재사용되지 않게 합니다.
- 모드 전환 후 서버 삭제 미완료 상태 유실 → `LOCAL_PENDING_SERVER_DELETE` 같은 영속 단계나 별도 플래그를 저장하고, 앱 시작·프로필 진입 시 멱등 DELETE를 재시도해 성공한 뒤에만 완료 상태로 확정합니다. 실패 문구도 모드 전환 전과 서버 정리 단계 실패를 구분해 안내합니다.
- 로컬 모드 직접 쓰기 누락 → `clearReadingDate()`는 로컬 컬럼만 명시적으로 비우는 경로를 추가하고, 독후감 공개 설정은 로컬 모드에서 네트워크를 호출하지 않도록 로컬 반영 또는 기능 비활성화 중 하나로 정책을 통일합니다. 같은 방식으로 직접 API를 호출하는 기록 메서드를 한 번 더 전수 점검합니다.
- 로그아웃 후 로컬 표지 잔존 → `clearAll()`의 파일 정리에 `bookCoverImageStore.clear()`를 포함하고, 다른 계정 로그인으로 로컬 데이터를 비우는 경로에서도 같은 정리 함수가 실행되는지 검증합니다.
- 로컬 직접 등록 표지 미표시 → 로컬 모드의 `createCustomBook()`은 선택 파일을 처음부터 `bookCoverImageStore`로 복사해 `coverImageUrl`에 상대 경로를 저장하고, 서버 재시도용 `createThumbnailPath`는 만들지 않습니다.
- 기존 원격 표지의 로컬 이전 누락 → 표지 URL도 마이그레이션 미리보기·다운로드·검증 대상에 넣고 `bookCoverImageStore` 매칭으로 전환하거나, 표지를 로컬 이전 범위에서 의도적으로 제외한다면 화면 안내에서 “모든 이미지” 표현과 오프라인 보장 범위를 명확히 제한합니다.
- 로컬 빠른 등록 무응답 → Repository 호출이 정상 반환되면 `serverId` 유무와 관계없이 등록 성공을 안내하고, 서버 동기화 완료 여부가 따로 필요하면 별도 상태·문구로 표현합니다.
