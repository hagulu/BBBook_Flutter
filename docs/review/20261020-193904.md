# 리뷰 결과

대상: 미커밋 변경 5개 파일(노트 상세 자동 스크롤, OCR 종료 확인, 공용 카메라/편집기 `confirmClose`, 완독 검색 "기록 포함" 토글). `flutter analyze` 통과.

## 요약
- 종료 확인 흐름과 이중 확인 회피(`closeWhole` 시 `_cancel`)는 의도대로 연결되어 있으나, 노트 상세의 자동 스크롤 루프가 종료 조건을 만족하지 못하는 상황에서 매 프레임을 계속 요청할 수 있다.

## 문제점
- [문제] `book_note_detail_screen.dart` `_scrollToBottom` — 반복 횟수 상한이 없다. `_lastMemoKey.currentContext == null`이면 `jumpTo` 후 `endOfFrame`(프레임 강제 예약)을 계속 반복한다. `_generateAiMemos`는 불투명 라우트(`BookNoteAiMemoComposerScreen`)가 위에 덮인 상태에서 호출되고, 가려진 라우트는 레이아웃되지 않아 새 마지막 항목이 생성되지 않는다. 현재는 composer가 `onGenerate` 완료 직후 `pop(true)`하므로 수 프레임 안에 수렴하지만, 화면이 가려진 채 유지되는 호출 경로가 생기면 매 vsync마다 프레임이 도는 구조다.
- [문제] 같은 파일 — `_visibleMemoCount`를 `build()`(`_buildContent`) 안에서 갱신하고, `_scheduleInitialScrollToBottom`이 build 중에 비동기 루프를 시작한다. 또 마지막 항목에만 붙는 `GlobalKey`는 메모가 추가될 때마다 인덱스를 옮겨 다니며 GlobalKey 재부착(reparent)을 일으킨다. 동작은 하지만 "마지막 항목이 배치되었는가" 판정만을 위해 쓰기엔 비용과 결합도가 크다.
- [문제] `shared_camera_screen.dart` `_requestClose` — 촬영/갤러리 처리 중에는 닫기 요청을 아무 안내 없이 무시한다. `confirmClose`가 없는 정책(메모 사진)에서는 `canPop: true`라 시스템 뒤로 가기는 그대로 닫히는데 X 버튼만 무반응이 되어 두 경로의 동작이 어긋난다.
- [문제] `shared_camera_screen.dart` build — 닫기 버튼이 `AppLoadingOverlay`(`blockInteraction` 기본값 true) 안쪽 `Stack`에 있어 카메라 초기화·재초기화 중(`_isLoading`)에는 누를 수 없다. `fullscreenDialog` 라우트라 iOS에는 뒤로 가기 제스처도 없으므로, 초기화가 길어지거나 멈추면 iOS 사용자는 화면을 닫을 방법이 없다. 이번 변경 전부터 있던 배치지만 이번에 정리한 닫기 흐름과 직결된다.
- [문제] `memo_ocr_capture.dart` `_joinWordsAsText` 문서 주석 — "정렬해 원래 / 공백으로 이어 붙인다"로 문장이 깨져 있다. 동작도 줄 구분이 `\n`에서 공백으로 바뀌었으므로 주석에 그 의도를 분명히 적는 편이 좋다.
- [문제] `finished_tab_view.dart` "기록 포함" 토글 — 버튼 높이가 32dp라 권장 터치 영역(48dp)보다 작다. 또 바깥 `Semantics(toggled:)`가 `container` 없이 `TextButton`을 감싸고 있어, toggled 속성이 버튼 노드가 아니라 상위 노드에 합쳐질 수 있다(실기기 TalkBack/VoiceOver 확인 필요).

## 개선 제안
- 자동 스크롤 무한 반복 → 루프에 최대 반복 횟수(예: 10회)를 두거나, `maxScrollExtent`/`pixels`가 직전 반복과 같으면 종료한다. 화면이 가려진 경우를 위해 `ModalRoute.of(context)?.isCurrent == false`이면 중단하고 복귀 시 다시 시도하는 방법도 있다.
- build 부작용·GlobalKey → 루프 안에서 `ref.read(bookNoteDetailProvider(_args))`와 `_importantOnly`로 개수를 계산해 `_visibleMemoCount` 필드를 없앤다. 마지막 항목 판정은 GlobalKey 대신 "도착 후 한 프레임 더 기다렸을 때 `maxScrollExtent`가 변하지 않음" 같은 위치 기반 조건으로 대체한다. 초기 스크롤은 데이터가 처음 도착하는 시점(`ref.listen`)에서 시작하도록 옮긴다.
- 카메라 닫기 무시 → 처리 중 닫기 요청이 들어오면 `AppSnackBar.info`로 안내하거나, `confirmClose == null` 경로도 `canPop`을 `!_isTakingPicture && !_isPickingImage`로 맞춰 X 버튼과 시스템 뒤로 가기를 일치시킨다.
- 로딩 중 닫기 불가 → 닫기 버튼 `Positioned`를 `AppLoadingOverlay` 바깥(오버레이 위 레이어)으로 옮겨 로딩 중에도 `_requestClose`를 호출할 수 있게 한다.
- OCR 주석 → "줄(lineOrder) → 낱말(wordOrder) 순으로 정렬한 뒤 줄 구분 없이 공백으로 이어 붙인다(발췌문을 한 문단으로 저장하기 위함)"처럼 고친다.
- 토글 접근성 → `minimumSize`를 `Size(0, 40)` 이상으로 올리거나 `tapTargetSize: MaterialTapTargetSize.padded`를 쓰고, `Semantics(container: true, toggled: includeRecords, ...)` 또는 `MergeSemantics`로 감싸 버튼 노드에 토글 상태가 붙게 한다.
